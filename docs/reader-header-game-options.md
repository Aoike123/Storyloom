# 读者主页：四种能直接玩一局的页头

> 已撤回，不实施。用户明确澄清：游戏性指探索感、参与感与操作趣味，不是独立小游戏；页头用于吸引评委，不能剧透。本文件及对应可玩设计稿仅保留为已否决草案。当前有效方向见 [页头吸引力与探索感方案](reader-header-invitation-options.md)。

状态：设计候选，等待用户选择。保留当前页面的深绿配色、字体气质和下方故事目录；只改原标语区域。继续遵循已确定的动效与交互优化方案。

新增要求：游戏性要强。因此每个候选必须有明确目标、可以推理或尝试的操作、可辨认的结果及重玩入口。只点一个兴趣标签、只抽一张推荐卡、只回一句俏皮话，均不作为本轮主要玩法。

## A. 开局救主角｜两步逃生挑战（首选）

页头：“门外的人，正在用你的声音叫你开门。你只有两次行动。”

这一局有清晰的作者预设世界规则：“它只能在你回应它后进门。”玩家通过线索发现规则，然后决定下一步。内容和分支必须由作者设计并审核，不将任意结果包装为 AI 推演。

演示流程：

1. 第一步选择：直接回应 / 悄悄看门缝 / 查看门边的纸条。
2. 直接回应会引来伪装者，立即出现失败结局；观察可发现无影子的脚，纸条明确写出“别回应”。
3. 第二步选择：保持安静，锁上门 / 追问它是谁 / 开门确认。
4. 守住门且未回应，得到“平安过夜”；回应或开门得到对应失败结局。
5. 结局展示刚才的两步行动，提供“换条路再来 / 看这个故事”。后一入口仅在有对应实际作品时启用。

游戏感来自观察—判断—后果，不来自倒计时或装饰性分数。两条第一步线索帮助重玩，失败文案说明是哪次行动触发后果；不惩罚读者阅读慢。

- 单局目标时长：15–30 秒，需真实用户验证。
- 页头布局：左侧当前情境与行动按钮；右侧保留已发现线索/两步记录，结果在原位置替换。
- 动效：选项按下后立即锁定本次选择，场景文字用一次约 180ms 的变化呈现；不让玩家等待打字机。
- 优点：很快展示“我的选择能影响故事”，重玩动力最强。
- 成本：每个推荐故事需要一小份经审核的预设分支内容，可复用组件。
- 边界：清晰标为“预设开场挑战”，不声称已经完成真实自由改写视频。

## B. 找出冒牌货｜点两处破绽

页头：“门外的室友，有两句话对不上。找出来，才知道该不该开门。”

页面提供一条背景事实和三条消息。演示背景：“你住 303；手机 18:00 就关机了，现在用平板收消息。”消息：“我到 302 门口了。”“刚才电话里不是说好了吗？”“我忘带钥匙了。”前两句分别与门牌、通话事实矛盾；第三句本身不足以判定。

玩家点击可疑消息标记线索，找齐两处后揭晓“别开门”。误选时给出具体提示，保留已经找到的线索；提供“换一题”，不把失败当作终点。

- 单局目标时长：15–25 秒。
- 页头布局：左侧场景与背景事实；右侧可点击的消息卡片，找到线索后描边并显示理由。
- 动效：被选消息轻微压下；正确理由原位出现，进度从 0/2 到 2/2，数值真实来自本局行为。
- 优点：有推理与发现的乐趣，适合悬疑内容；无需视频和模型等待。
- 成本：每题需人工核查逻辑和唯一/合理答案，避免仅靠含糊语义判错。
- 边界：文案为原创设计示例，不伪装为某篇知乎原文。

## C. 脑洞生存盲盒｜抽到什么，就用什么破局

页头：“给你一个离谱开局，看看怎么活下来。”

点击“抽取开局”，同时揭晓身份、困境、道具；还要做一次决策，才算完成一局。每个开局有可见规则或提示，结果由玩家行动决定，不仅随机发一个结局。

演示开局：

- 实习保安 / 影子溜进电梯 / 手电筒。规则：影子只能在光照到时移动。关灯可以让它停住。
- 末班车乘客 / 车一直开回昨天 / 一支笔。规则：列车按车票日期停靠。修改票面日期是可行办法。
- 图书管理员 / 书里的怪物跑到门口 / 一张书签。规则：合书前夹入书签可封住该页。玩家选择正确用法可把怪物留在书里。

选择结果后展示“你用了什么 / 发生了什么”，可抽新局或重试当前局。故事规则属于示例世界设定，必须在行动前让玩家有机会看懂。

- 单局目标时长：15–30 秒。
- 页头布局：一行紧凑的三张签卡，下方一句困境规则和三个行动。
- 动效：抽签只进行一次短切换，总时长不超过约 300ms；不使用老虎机长动画或虚假生成进度。
- 优点：脑洞强、好重玩，题材可以随故事库更换。
- 成本：预设小关卡与答案内容；首期不现场调用模型生成关卡。

## D. 猜下一秒｜视频暂停竞猜（视频优先的首选）

页头：“先看两秒，猜她下一步会做什么。”

用户点播放后先看短片，在经人工标注的悬念处暂停；选一个预测后立即继续播放，以真实画面揭晓答案。正确/错误反馈只与该视频事件比较；不显示伪造的全站猜中率。

演示使用项目现有 8 秒动漫样片：先播约 2 秒，选“转头看过来 / 走进列车 / 沿站台离开”，继续播放后揭晓角色转头看向镜头。该素材仅用于交互设计预览，不能据此声称某个故事已发布。

- 单局目标时长：10–20 秒。
- 页头布局：右侧/上方是视频，左侧/下方是一个问题和三个预测；问题就地出现，不重排整个页面。
- 动效：暂停保留当前帧，选择后马上续播；片尾呈现简短结果和“再看 / 换一段”。声音设置保持一致。
- 优点：读者首先看到真正的视频，同时主动参与，最符合“重视频表现”。
- 成本：每条短片人工标注暂停点、选择项、正确答案及揭晓点，播放前验证媒体可用。
- 边界：预测不会修改原片。无法加载时保留封面并提供换一段/去目录，不能卡住首页。

## 如何选择

| 想强调的体验 | 推荐 |
| --- | --- |
| 我做了选择，所以故事不一样 | A：开局救主角 |
| 我发现了别人没发现的线索 | B：找出冒牌货 |
| 我还想抽一个离谱开局再玩 | C：脑洞生存盲盒 |
| 我先看到了好看的视频，又参与了一次猜测 | D：猜下一秒 |

综合项目定位，优先在 A 和 D 中选一个作为主页头部。A 展示剧情参与，D 展示视频效果。其余玩法可以后轮换，不同时塞满首页。

## 共同交互与实现边界

- 导航和原故事目录继续可见，游戏完全可跳过。首次不弹规则说明，不要求登录或输入。
- 第一次点击即可开始；不在首页要求读者先填写提示词、等待模型生成或者挑选身份问卷。
- 不使用真实倒计时强迫选择；不加入金币、抽奖付费、榜单、虚假玩家头像或编造热度。
- 结果与行动明确对应，展示本次线索与路径；不隐藏关键规则，再用随机惩罚制造难度。
- 已玩内容保留清晰来源，只有关联到实际作品时才出现“看这个故事”；不把小游戏随意导向无关原著。
- 四套方案均可先用预设内容实现；真实自由改写能力继续单独建设。两者的状态和文案不混淆。
- 约 160–240ms 的轻动效，用户连续点击时只生效一次；反馈位置和媒体画幅固定，减少动态效果模式仍可完整游玩。
- 本次演示只修改设计稿本地状态，不发起模型调用、不修改应用代码或作品数据。
