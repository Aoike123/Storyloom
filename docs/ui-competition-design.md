# 叙间 · 竞赛体验 UI 设计方案

> 已撤回：用户反馈保留当前选择页的布局、配色和视觉风格，重点优化动效与交互流畅度。本文的视觉重设计与上一版交互稿不作为实施依据。当前有效方案见 [动效与交互优化方案](ui-motion-interaction-design.md)。

日期：2026-09-13。阶段：设计提案，尚未实施。设计目标是让首次访问者被视频吸引、无需讲解完成观看与留想法，并能理解故事如何变成漫剧。

## 1. 产品主张与设计取舍

**看到这里，换你出招。**

叙间是一间可以留下脑洞的私人放映室。视觉以内容为主，观看过程保持安静，暂停后再邀请参与。整体气质为“电影海报的张力 + 阅读产品的舒适 + 轻量游戏的参与感”。

体验优先级：视频可看且顺畅 → 第一次操作无需解释 → 明白自己的操作产生了什么 → 画面和品牌有记忆点 → 创作流程易理解。

这次只设计，不调整现有应用、业务数据、发布状态或模型配置。交互稿使用项目已有的 8 秒本地视频压缩预览；其出现不代表该素材已作为作品发布。故事与选择文案属于排版和交互样例。

## 2. 当前问题与证据

本次依据 `AUTHOR_WORKFLOW.md`、`web/app/ReaderExperience.tsx`、`reader-catalog.css`、`author/page.tsx` 及 `author.css` 进行检查；运行时可用性尚未重新验收。

| 当前情况 | 评委的感受 | 设计调整 |
| --- | --- | --- |
| 首页约 460px 的文字 Hero，主按钮为“挑一个故事” | 首屏不知道成片效果，要先向下找内容 | 首屏直接呈现主推成片画面和“开始观看”，主推位置取真实可播放作品 |
| 没有成片的条目整体置灰，且可直接进入制作 | 容易误认为不可用，观看者误入制作流程 | 可播放作品进入“现在开场”；未制作为“待开拍故事”，保留清晰文字、正常对比度，显式写“读原文 / 去创作” |
| 观看页始终显示右侧 textarea 与说明 | 还没看懂故事就被要求输入 | 默认大画面；点“这一秒，我有个想法”后暂停并展开输入区 |
| 交互按钮依赖暂停状态，初次面对空输入框 | 不知道何时、写什么、写了会怎样 | 一个按钮自动暂停并打开输入区，提供 3 条简短灵感和自由输入 |
| 保存完成后长说明逐字出现 | 关键反馈延迟；“保存”容易被理解为“生成” | 立即显示“想法已保存 · 00:xx”，并提供继续观看；清晰说明视频保持原作 |
| 标题、标签、说明里大量 9–12px 字体及偏淡颜色 | 投屏、小笔记本和移动设备阅读吃力 | 正文 16px，辅助信息通常 13–14px；增强对比度，关键状态不缩成角落小字 |
| 创作页同时展示原文、多阶段与完整任务列表 | 心理上像进入后台，需要先理解流程 | 原文收进抽屉，当前阶段围绕图片/视频展示，一个明确下一步；制作动态按需展开 |

当前已具备免登录、故事目录、视频连续播放、暂停与保存想法，以及作者图片确认和成片发布的接口与页面逻辑。**读者自由改写后的真实视频分支与接回主线仍未完成。** UI 不可把保存成功包装成剧情已改变。

## 3. 信息架构

顶栏保留“叙间”品牌、“发现故事”和较轻的“创作台”入口。不要让第一次访问先选读者/作者身份。首页以读者模式打开。

| 页面 | 唯一主要目标 | 主要内容与动作 |
| --- | --- | --- |
| 发现故事 `/` | 点开第一部作品 | 主推视频、开始观看、可播放作品、待开拍故事 |
| 放映室 `/?story=…` | 看清楚、看下去 | 大播放器、短标题、时间轴、暂停留脑洞、声音与全屏 |
| 暂停状态（同页） | 表达一个想法 | 保留暂停画面、3 条灵感、自由输入、保存并继续 |
| 我的脑洞（同页抽屉） | 找回刚才的想法 | 作品标题、时间点、想法、回到这一秒；第一阶段按当前浏览会话呈现，不暗示跨设备保存 |
| 创作台 `/author` | 完成当前制作决定 | 选故事 → 定风格 → 看图确认 → 审片发布 |

浏览器返回键恢复上一个页面及目录位置。作品分享/深链接保留当前已支持的 story 参数。不要为视觉改版强行重建路由体系。

## 4. 评委首次体验脚本

以下时间是设计验收目标，不是已测性能或生成速度承诺。

1. **0–5 秒**：看到真实视频封面、作品标题和一句“看到这里，换你出招”，知道这是可观看、可参与的故事产品。
2. **5–15 秒**：点击“开始观看”，在同一次用户操作里开始播放。无需登录、选模型、填文字、阅读引导弹窗。
3. **15–35 秒**：欣赏样片。首次仅在播放器下方提示一次“有想法时，随时暂停”，不强制打断剧情。
4. **35–50 秒**：点“这一秒，我有个想法”。影片暂停在当前帧，右侧出现小面板；移动端置于播放器下方。点一条灵感可填入，也能自由修改。
5. **50–60 秒**：保存后看到“想法已保存 · 00:xx”和自己的原句，再点“继续观看”。
6. **60–90 秒（可选）**：打开“这部怎么拍的”，浏览原文署名、风格图和成片过程，再进入创作台体验视觉选择。

首轮体验必须靠预先准备、已审核发布的成片成立。评委观看期间不应被迫等待整部视频生成。若要展示预生成分支，明确标为“预生成体验”；自由输入只能按实际能力反馈。

## 5. 关键页面设计

### A. 首页：让成片承担第一印象

- 桌面首屏：文字占约 35–40%，视频画面占约 60–65%；超过中等宽度可采用海报式左右构图。主标题 44–64px，最多两行，副文案最多两行。
- 主推内容：一个经过审核的真实作品、统一封面、时长、题材、来源署名、一个“开始观看”主按钮。已有断点时变为“继续观看 · 00:xx”。
- 默认先呈现 poster；加载条件合适时可播放 5–8 秒静音预览，提供暂停，播放一次后停留。预览不承担必要信息，不依赖它才能发现入口。
- 原著来源与 AI 改编标识紧邻作品信息；只标明实际覆盖的短场景，不暗示整部原作已经完整影视化。
- 第二屏“现在开场”仅收录发布且媒体可用的作品；每张卡为封面、标题、题材、时长、观看按钮。作品少时自然展示 1–3 张，不伪造作品数、热度或评分。
- 下方“下一部，由谁开场”放待制作故事，默认折叠到一行摘要或较小卡片。此处保留“读原文 / 去创作”，不以不可用的大灰卡占满第一页。
- 只有一部成片时扩大这部作品的展示，不重复同一素材伪装作品库。零成片时改为真实空状态和“阅读故事”；若另有可看的样片，单独标记“制作样片”。

### B. 放映室：画面占主位

- 默认单栏大播放器；桌面建议页面宽度 1200–1440px 内自适应。页面顶栏和作品信息压缩成两条短信息，不占据主要高度。
- 横屏、方形、竖屏内容都保留完整画幅。方形/竖屏置于深色舞台中居中；不得拉伸或为填满而裁掉角色、字幕、关键线索。首屏封面允许单独选择构图。
- 播放时不显示常驻侧栏、不显示任务流程和模型信息。核心动作只有播放/暂停、进度、音量、字幕（有真实字幕时）、全屏、留下脑洞。
- 时间轴使用整部可播放内容的累计时长；片段边界弱化为刻度。片段切换保持播放意图与音量，避免黑帧、回到 0 秒、重复播放、突然爆音。
- “这一秒，我有个想法”是带文字的清晰按钮；Space 可暂停/继续，Esc 关闭脑洞面板，输入文字时不抢占快捷键。
- 视频结束后保留最后一帧，出现“回看我的脑洞 / 再看一次 / 换个故事”，不突然跳回目录。

### C. 暂停与脑洞：一句话就能参与

上方显示“停在 00:24，这一刻你想怎么做？”；下方保留暂停画面、三条与已播放内容相关的灵感、自由输入和一个主按钮。

示例灵感：“先问清楚”“假装没看见”“我有别的主意”。实际文案必须依当前故事和已播放内容编写，不预告未来线索，不暗示只允许三个选项。

- 点灵感只是填入输入框，可继续编辑，不直接提交。
- 点保存后立即给出等待状态并防止重复提交。保存失败保留原文和时间点，显示“没保存成功，再试一次”。
- 保存成功后卡片呈现原句与时间点；按钮改为“继续观看”。保留草稿；关闭面板不丢失输入。
- 当前版本文案：“保存这一刻的想法”；说明：“会保存你的脑洞，当前视频不会改变。”这句话在提交前可见。
- 不用长段打字机动画延迟关键反馈；可给保存图标 160–200ms 的一次轻反馈，不做全屏庆祝。

**未来真实改写能力完成后的分层设计：**

| 状态 | 用户看到的内容 | 可做什么 |
| --- | --- | --- |
| 理解想法 | 对改动的简短复述 | 修改 / 取消；不要把未生成内容当成已发生 |
| 制作新片段 | 实际阶段与已耗时 | 查看暂停帧、继续看原作；有可靠样本才给估时范围 |
| 新片段可播放 | “你的这一幕，准备好了” | 用户点击切换，不能突然抢走当前播放 |
| 剧情冲突 | 用故事语言说明哪条已发生事实冲突 | 调整一句话 / 采用可行建议 |
| 生成失败 | 保留想法、原片、已生成材料 | 返回原作 / 查看恢复选项；收费结果不明时不盲目重试 |
| 分支接回主线 | 时间轴标记“你的改写”，正常继续播放 | 对比原版、回看；不能仅用文案声称已完成衔接 |

这些未来状态作为产品方向保留，不进入当前竞赛主路径，除非真实闭环已通过验收。

### D. 创作台：看着画面做决定

将用户可理解的流程收敛为四段；现有后端六阶段继续保留并映射，无需为界面改动重做任务系统。

| 用户看到 | 现有阶段/逻辑 | 页面中心 |
| --- | --- | --- |
| 选故事 | 目录与原文导入 | 故事摘要、原著署名、展开原文；打开不触发付费 |
| 定风格 | style / preparing | 3 张风格视觉卡 + 推荐原因；选中后可补一句要求 |
| 看图确认 | assets_review | 人物与场景大图；逐张查看、简短修改意见、确认后生成分镜 |
| 审片发布 | film_review / published | 完整顺序播放、镜头缩略条、修改、发布到读者空间 |

- 风格卡必须有视觉样张。通用样张标记“风格参考”，故事专属试拍标记“本故事试拍”；没有样张时不伪装已生成。
- 不要求初次使用者理解“剧情气质”“资产版本”等词。默认推荐有依据时预填；允许“告诉我更多要求”展开高级输入。
- 当前步骤的图/视频占主区，原文抽屉和制作动态处于次级位置。需要人工确认的区域明确突出。
- 图片可放大、前后对比；按图修改的输入贴近对应画面，保存修改意见后保留上下文。
- 付费生成开始前明确提示将调用供应商；保留已有授权与图片/发布确认，不为“无门槛”绕过收费确认。实际费用以供应商账单为准。
- 发布完成后的主要动作是“去看我的成片”；模型配置放在创作台设置中。

## 6. 视觉语言

推荐电影感暖橙方向，保留“叙间”名称和“每个故事，都有另一种可能”的品牌文案。避免再用满屏低对比度浅绿文字。

| 设计项 | 规范建议 |
| --- | --- |
| 放映舞台 | 固定深炭黑 `#101315`，让视频成为亮度中心 |
| 页面底色 | 深色 `#101315` / 浅色暖白 `#F7F5F0`，跟随系统；创作区可采用更明亮的阅读面 |
| 深色卡片 | `#1B2024`，边界 `#343C42`；减少套卡片与大阴影 |
| 主文字 | 深色底 `#F5F2EB`；浅色底 `#202623` |
| 辅助文字 | 深色底 `#B3BBC0`；浅色底 `#59635E`，实施时逐项量测对比度 |
| 品牌强调 | 暖橙 `#FFB077`，深色字 `#211A15`；只用于主要动作和当前状态 |
| 可比较方向 | 备选青绿 `#C9DFAB`，保留旧品牌延续性；结构与交互保持一致 |
| 字体 | UI 使用系统中文无衬线，海报主标题适当使用宋体；不依赖联网字体才能正确展示 |
| 字号 | 首页标题 44–64px、页面标题 28–36px、卡片标题 18–22px、正文 16px、辅助 13–14px |
| 间距与圆角 | 8px 基础节奏；组件内 16–24px，区块间 32–48px；卡片 12px，按钮 10px |
| 图标 | 统一 Lucide；核心动作有文字，不以抽象图标让用户猜 |
| 动效 | hover/选择 120–180ms，面板展开约 200ms；不使用持续背景运动、无意义打字机与循环粒子 |

电影感来自封面、构图、标题层级、画面空间与声音控制。趣味性来自“我的一句话被记在某一秒”及未来真实选择后果。首期不增加积分、排行榜、抽奖、弹幕墙或假用户数据。

## 7. 移动端与无障碍

- 360–430px：顶栏保持品牌和必要入口，标题适当缩小；播放器全宽，脑洞面板位于其下方，软件键盘弹起后提交按钮仍可触达。
- 768px 左右：首页左右构图改为上下；优先显示画面和主动作。1080px 以下创作流程渐进换行。
- 关键按钮触控区域目标至少 44×44px，所有核心操作能用键盘完成；保留明确焦点样式。
- 正文对比度目标至少 4.5:1，大字号至少 3:1；不仅凭色彩区分成功、等待、失败。依据 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- 尊重减少动态效果偏好；动态效果不是理解页面的必要条件。
- 不自动有声播放；自动预览失败时保留封面和手动播放按钮。浏览器对有声自动播放通常有限制，具体规则依环境而异，依据 [MDN 自动播放指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。
- 字幕控制仅在存在真实字幕时提供。无声音的作品明确标注，不能用装饰性声波暗示正在配音。

## 8. 必须设计的异常状态

| 场景 | 页面呈现 | 恢复动作 |
| --- | --- | --- |
| 首次加载目录 | 稳定尺寸的封面骨架，保留品牌和导航 | 失败后明确重试 |
| 有缓存但目录服务失败 | 可看的内容继续可看，显示目录更新时间 | 用户主动刷新 |
| 零可播放作品 | 真实空状态；有独立样片才提供标记明确的样片入口 | 阅读故事 / 去创作 |
| 视频媒体失效 | 保留标题和封面，显示“这一幕暂时无法播放” | 重试 / 换一部 |
| 片段缓冲 | 保留上一帧或封面，显示正在缓冲；不跳回首页 | 超时给重试 |
| 暂停但没想法 | 3 条启发语 + 自由输入 | 继续观看 |
| 保存超时/失败 | 保留输入和暂停位置，错误紧邻提交区 | 重试保存 |
| 作者生成中 | 实际阶段、已耗时、已生成图；不用假百分比 | 离开后可返回 |
| 作者任务失败 | 把问题集中呈现，保留成品 | 查看原因 / 按实际能力恢复 |

## 9. 分阶段实施

### P0：直接影响评委首次成功

1. 准备至少一部可实际播放、审查过画面和声音、来源与范围清楚的主推成片。
2. 首页主推视频、可播放故事优先、待制作目录下沉。
3. 放映室全宽与画幅适配、明确播放动作、封面/缓冲/失效状态。
4. 暂停再出现脑洞面板；灵感填入、保存反馈、继续观看和草稿保留。
5. 字号、对比度、移动端、焦点、触控区域。
6. 明确“保存想法”的能力边界；不要在界面先许诺真实生成。

### P1：完善产品感

1. 创作台四步映射、视觉风格卡、原文抽屉。
2. 图片放大/对比与审片缩略条。
3. 观看断点和脑洞历史（定义本地/会话保存范围）、作品详情与来源。
4. 细腻且克制的单次反馈动画、视频预加载和片段衔接优化。

### P2：真实能力完成后扩展

真实视频改写、可切换分支、主线回归与原版对比。先验收内容生成和状态一致性，再接入新 UI；不计入本次纯 UI 修改即可完成的范围。

## 10. 验收方法与通过条件

找 3–5 位没看过产品的人，只发入口，不讲解。记录首次点击、首次播放、首次保存想法所用时间，以及他们认为“保存”做了什么。

- 首屏 5 秒内能说出“这是看故事视频、可以留脑洞的产品”；这是研究目标，需实测。
