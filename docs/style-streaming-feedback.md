# 风格推荐的实时构思反馈

已实施：2026-09-14。

原先的文本模型请求使用非流式响应，前端每 5 秒轮询完整作品；后台领取任务后没有更新“等待执行”。因此等待过程只有空进度条，结果一次性出现。

## 当前行为

- 风格推荐在同一次模型请求中启用流式输出，先返回给作者看的简短构思摘要，再依次返回风格、剧情气质与适配原因。
- 任务保存实际连接阶段、构思摘要和方案草稿，通过 SSE 向页面同步。界面不展示原始 JSON，也不把打字动画当成模型思考。
- 构思区与方案位置保持稳定。已到达的字段直接呈现；完成全部格式检查后才允许选择方案。
- 刷新或重新进入会恢复已保存的内容。SSE 断线时保留内容，原有定期同步继续工作；模型请求不会因此重新提交。
- 模型自身思考通道只用于显示活动状态，不保存原始内部推理。界面展示的是模型专门生成的简短创作摘要。
- 原有付费确认、模型选择与思考开关不变。调用次数和 usage 仍在原计费记录中累计。

## 边界

风格推荐是第一轮接入；其余步骤现已扩展，见 [全流程创作与制作反馈](production-progress.md)。旧任务没有历史构思内容时明确说明，不补造过程。

若兼容接口对流式请求仍返回普通 JSON，会使用本次结果并说明一次性返回；不额外重发调用。若接口拒绝流式参数、连接中断、输出截断或格式检查失败，保留草稿并显示问题，不将草稿作为可选成品。

## 验证

- 使用隔离数据库和模拟供应商传输，覆盖中途摘要、部分方案、独立思考信号、SSE 中间状态、最终 usage、普通 JSON 兼容、断线、截断、格式错误、任务归属及旧 worker 隔离。
- 浏览器检查桌面与 390px 窄屏；方案生成与完成时卡片起始位置相同，完成后可选择，失败后保留不可选草稿。
- 测试未调用付费模型。当前供应商真实流式返回速度与质量尚未通过新增付费调用验证。
