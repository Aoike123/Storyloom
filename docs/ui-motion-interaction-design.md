# 叙间 · 动效与交互优化方案

状态：设计阶段，尚未修改应用代码。

补充范围：用户明确要求读者主页页头更有吸引力，有探索感和操作趣味，但不做独立游戏、不剧透。页头内容按 [页头吸引力与探索感方案](reader-header-invitation-options.md) 另行选择；此前四种开场小游戏方案已撤回。本方案关于当前页面视觉与其他区域的保留要求继续生效。

本方案替代此前的视觉重设计。用户认可现有选择页，保留其布局、配色、字体、封面、卡片形态和文案气质；重点优化操作反馈、切换连续性、等待体验与视频衔接。

## 体验方向

用户点击后立刻知道操作已被接收；变化发生在刚才操作的位置；新内容接替旧内容时保持空间连续；返回时仍能找到刚才的故事。整体保持现有的安静、轻盈气质。

选择页保持原样，改善六个动作：悬停、按下、筛选、进入、等待、返回。静态截图应与当前页面基本一致，差异主要体现在操作过程中。

## 从现有实现确认的情况

以下为代码检查结果，尚未通过运行时性能录制确认掉帧或耗时，需区分设计问题和性能问题。

| 已确认的实现 | 可能影响 |
| --- | --- |
| 目录和放映页通过条件渲染直接替换，没有显式切换过渡或滚动位置恢复 | 页面跳变；从目录下方进入后，返回位置缺乏保证 |
| 制作入口使用普通链接，切换已有制作使用整页跳转 | 重载和重新取数容易造成割裂感 |
| 卡片 hover 的位移在样式末尾被取消，筛选后网格直接重排 | 点击目标与筛选变化缺少连续反馈；无需因此让整张卡片重新漂浮 |
| Typewriter 每 22ms 增加可见文字；多个风格说明并行执行 | 返回内容继续逐字显现，难以立即比较，文字换行可能推动下面的按钮 |
| InteractionFeedback 有内容时插入、无内容时移除；忙碌态同时含旋转图标、滑动条和逐字文字 | 提示区出现时可能推挤布局；等待状态动得较多，但不一定传达更多信息 |
| 读者视频按 index、审片视频按 clip.id 更换 key，导致换段时重建播放器 | 重新加载/解码可能产生黑帧、控制条变化或停顿；不能只靠动画修复 |
| 视频 timeupdate 更新读者页顶层状态；作者每 2.5 秒同步整份作品数据 | 属于需测量的渲染范围，不能仅凭轮询频率就认定有性能问题 |

相同 text 不会因为普通轮询自动重启 Typewriter；问题重点在新文字呈现与容器尺寸变化，不误诊为每次轮询都重播。

## 1. 选择页：保留外观，让每次操作更明确

### 卡片与按钮

- 鼠标进入：沿用现有颜色，卡片边线和操作文字在 140–180ms 内轻微增强；封面可选最多 1.015 倍缩放，限定在图片区域。
- 鼠标离开：平滑回到原样，不产生位移回弹。
- 按下按钮：80–100ms 的轻反馈，可采用颜色压深或 0.985 倍缩放；100–140ms 恢复。触控与键盘有同等明确反馈。
- 整张卡片不弹跳、不倾斜，文字和标签不跟着放大。不添加新的装饰元素。
- 点击进入后马上显示已响应状态，防止连续点击；过渡不能成为必须等待的额外延迟。

### 状态筛选与搜索

- 沿用当前筛选按钮的形状与颜色，选中底色在约 160ms 内移动/过渡。
- 搜索输入即时响应，不让光标等待列表动画。中文输入过程中不因未确认的拼音反复触发结果动效。
- 结果更新时保留外层容器，离开的条目短淡出、留下的条目在约 180–220ms 内移动到新位置，新条目轻淡入；动画只作用于实际变化的条目。
- 连续快速切换时以最新选择为准，取消旧过渡，不排队播放。
- 内容少时不人为加入防抖延迟；条目多且实测出现卡顿时再优化计算与渲染。
- 刷新目录时保留已显示内容和筛选条件，只让刷新入口显示忙碌状态。失败信息在工具栏附近出现。

## 2. 进入与返回：让两页接得上

默认方案是轻量的就地反馈与短过渡，保留现有页面结构。

1. 点击作品后，当前卡片立刻反馈，记录来源卡片、筛选条件与滚动位置。
2. 页面内容采用 180–240ms 的短淡入、最多 6–8px 位移；顶栏保持稳定。关闭动画时直接切换也应正确工作。
3. 数据未准备好时，新页呈现与最终布局同尺寸的占位和真实封面，不出现整页白闪。
4. 返回目录恢复筛选、搜索、原滚动位置及键盘焦点，不要求用户重新找故事。
5. 在业务允许的前提下改为站内导航与缓存复用，减少完整页面重载。预取只读取页面与必要数据，不能触发作品生成或收费任务。

封面从卡片过渡到详情的共享元素效果可列为第二轮细化；需在真实页面上验证坐标、画幅和浏览器回退后再采用。第一轮不依赖这一效果达成顺滑。

## 3. 加载与反馈：等待期间页面要稳

- 点击立即改变按钮状态。快请求直接呈现结果，不为了展示 loading 强制等待。
- 操作提示留在按钮附近，按钮宽度不随“提交 / 提交中 / 已完成”变化。
- 首次无数据使用与最终卡片同尺寸的占位；已经有数据时保持旧内容，后台更新后局部替换。
- 图片先保留固定画幅，加载并可显示后短淡入；错误时同一位置呈现重试，不塌陷高度。
- 等待动画默认只保留一种。短请求用按钮内旋转图标；长生成展示真实阶段、必要时展示进度。不要把 spinner、跑动进度条和打字机同时作为默认反馈。
- 成功或错误的结论一次性完整显示，不能让用户等待逐字阅读后才知道结果。
- 若要保留 AI 构思的趣味，只有首次返回的非关键说明可短暂渐显，并预留完整文字所占空间；风格名称、选中状态、错误信息和提交结果立即可读。
- 完成状态使用 160–200ms 的一次勾选反馈，随后保持安静。后台刷新不重复播放入场或完成动画。
- 错误消息在原区域显示，保留输入与已选内容，重试入口紧邻错误。

## 4. 视频与剧情互动：优先消除真实停顿

- 打开已发布作品，立即呈现封面和播放器；主动点击的播放意图延续到媒体就绪，不能让用户误以为第一次没点中。播放失败保留明确的手动入口。
- 换段前有节制地准备下一段，先验证是否能稳定维持播放器和控制状态；若采用双缓冲，严格限制同时播放与音轨输出。
- 切换前保持当前帧或封面，下一段首帧可显示后再交接。不能用一段漂亮的淡入掩盖实际重复、跳段或错过起始帧。
- 保持音量、静音、播放/暂停意图与整部作品的累计时间。快速跳段时只接受当前选择，旧加载事件不得覆盖新段。
- 暂停立即停画面并记录位置；当前右侧互动区保持原位置，通过标签、边线或输入焦点提示“现在可以写想法”，无需为此重排观看布局。
- 提交脑洞只锁定相关按钮；成功后在原区域呈现时间点和原句，继续观看入口明确。失败保留草稿。
- 播放相关的高频更新尽量限制在时间显示和必要的播放器区域；先用性能录制定位，再决定是否拆分组件或节流。
- 首期保持实际“保存想法”能力，不引入新分支玩法或改变当前功能范围。

## 5. 创作端：沿用六阶段，平顺地更新当前步骤

- 保留现有六阶段步骤条、原文区和制作区布局。
- 选择风格时选中背景、边框和勾选在 140–180ms 内变化，立即同步输入项。风格说明一次性呈现，避免多张卡片同时逐字增长。
- 后台进度同步只更新变化的状态，不让整页、卡片和标题重复入场。
- 阶段变化时先稳定显示新阶段，再对当前内容做一次短过渡；不自动把正在阅读原文的用户拉走。
- 用户刚主动点击“下一步”后，可把新阶段标题滚到可见位置；被动后台更新只提示，不抢焦点。
- 任务列表展开/收起保持标题和操作入口稳定，约 200ms 完成。只有用户主动展开才显露更多内容。
- 保留付费、图片确认、成片发布的现有业务关口；本方案不改变这些流程。

## 统一动效规范

| 类型 | 建议时长 | 使用范围 |
| --- | --- | --- |
| 按下反馈 | 80–100ms | 按钮、可选项 |
| 悬停/选中 | 140–180ms | 边线、底色、图标 |
| 内容更新 | 180–220ms | 筛选、短反馈、图片出现 |
| 页面/阶段切换 | 180–240ms | 内容区过渡 |

这些数值是设计初值，不是已测结果。统一采用快速响应、平缓收尾的曲线，最多轻微位移；不使用明显弹簧、夸张弹跳、全页模糊或长距离滑动。优先用透明度与 transform 实现视觉变化，实际布局变化需测量和验证，避免每帧反复读写布局。

减少动态效果模式下取消位移与缩放，保留即时状态反馈。键盘焦点、选中状态与加载文字始终清晰；触屏不依赖 hover 才能看到入口。

## 实施顺序与验收

**第一轮：先修会让人觉得卡住的问题。**

1. 页面进入/返回与位置恢复。
2. 固定反馈与素材容器尺寸，取消关键消息逐字展示。
3. 点击后的即时状态、防重复操作与草稿保留。
4. 视频换段衔接与播放状态保持。

**第二轮：打磨细节。** 筛选重排、卡片/按钮微反馈、步骤变化和列表展开。动效时长在真实页面里统一微调。

验收直接使用现有界面：

- 静态视觉与当前选择页一致；不引入新的首页、配色或卡片体系。
- 反复筛选、搜索、进入、返回后，位置与选择保持正确，无旧动画排队、重复跳转、文字重叠或焦点丢失。
- 快请求不增加人为等待；慢请求有即时反馈，已有内容不消失。
- 提示出现、文字返回、图片加载时，用户正在操作的按钮不因内容增长突然移位。
- 多段视频不出现可感知的黑闪、重复/跳段或音量突变；慢网状态能明确解释，不能把缓冲说成流畅。
- 在桌面、触屏、键盘与减少动态效果模式下完成同一流程。
- 对真实录制中出现的卡顿记录触发动作、渲染耗时和原因；不以“加了 transition”或单次顺畅替代性能验收。

预期修改范围为读者页、目录样式、反馈组件、作者页及对应样式；具体导航和播放器改动需实施时再定。本轮交付设计方案，未实施代码改动。
