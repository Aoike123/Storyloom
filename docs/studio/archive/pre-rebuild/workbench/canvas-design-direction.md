# 画布优先设计方向

版本：1.3 · 2026-10-03 · 状态：全文荧光区域、片段跳转、来源出线及成片布局已确认；工程契约与视觉细节待完善

本文件定义当前空间方向，取代固定三列和「叙事画布／章节编排」两套布局。第 7–11 节记录本轮设计稿确认的交互及后续工程边界；未列为确认的具体制作操作继续讨论，功能实现状态另行记录。[设计规范](design-spec.md)中的唯一归属、准确版本、审核和历史快照规则继续有效。

## 1. 空间骨架

```text
┌────────────────────────────────────────────────────────────────┐
│ 叙间 / 项目名                                 搜索  任务  主题 │
│ 当前工作标签…（数量、名称与片段范围的呈现方式待定）             │
├──────────────────┬──────────────────────────────────┬────────┤
│ 故事来源区       │ 当前范围 / 对象路径              │ 右工具 │
│ 原文 / 片段      │                                  │ 属性   │
│                  │    当 前 任 务 画 布             │ 引用   │
│ 全文阅读与选取   │                                  │        │
│                  │    原文范围与工作对象局部连线    │ 任务   │
│ 整块荧光区域     │    平移 / 缩放 / 自由排布        │ 定位   │
│                  │                                  │        │
│                  │    当前步骤对话入口固定在底部    │        │
│                  │                       视野控制   │        │
└──────────────────┴──────────────────────────────────┴────────┘
```

这是切分／裁减、剧本、分镜、资产任务的空间示意：左侧是贯穿项目的故事全文来源区，右侧主体均为可平移、缩放、自由拖动对象的无限画布。原文提供连续阅读、划选和来源对照；进入切分／裁减任务时画布恢复片段编辑职能。成片是例外，剪辑组件铺满右侧主工作区，左侧故事来源／片段列表同时承担资源区，详见第 9 节。右侧属性对应实际选中的项目对象，每个步骤底部都有自然语言对话入口。全局项目树与旧工具轨不恢复，不设独立版本入口。本轮更新的是设计和后续安排，已完成的框架范围仍见[框架计划](implementation-plan.md)。

- **顶部导航随工作模式设计**：此前「故事、制作、素材、成片」是框架展示中的暂定划分，数量、名称与层级不再作为固定约束。故事总控负责原文切分和项目进度；点击确认片段倾向进入大标签，具体承载方式继续设计。剧本、分镜、资源生成和剪辑的职责保留，最终如何安排工作标签另行讨论。
- **多场画布默认展开**：制作按场整齐排列多个镜头，素材按资源排列节点。分组直接在画布中表达，不设置场次选择器或常驻图层索引。
- **画布组织自由内容**：稿件、篇章／场／镜头、素材需求、独立资源按当前任务组织。自由摆放不改变真实归属或叙事顺序；成片的时间轴属于剪辑编排，不采用自由画布坐标。
- **阅读视图、片段选择与执行任务分开**：原文／片段是左侧的阅读组织方式；普通制作任务中，切换片段恢复目标片段的工作状态和画布职能。成片中的来源选择用于资源浏览，保留当前项目剪辑。排队或运行的任务继续执行，用户可从项目任务队列回到原工作位置。左侧全文区宽度、展开与收起继续设计。
- **属性依附所选对象**：右侧属性展示实际选中项目对象的内容、真实归属、来源、版本和状态，不用任务介绍代替对象属性。引用、任务和定位按需展开；底部对话依附当前步骤、片段和所选对象，不要求显示 Agent 名称。
- **定位能力重新设计**：顶部切换、真实路径、画布分层、搜索与定位协作；是否需要小地图或按需大纲由 D02 决定，不把旧左树直接搬回来。
- **跨标签切换由用户主动操作**：查找结果、引用素材或使用位置默认在当前工作区查看详情。用户点击确认好的故事片段，可以主动进入对应的大标签，这是当前倾向，尚未锁定标签的名称与组织方式。显式切换后恢复各工作区的范围与视野；任务完成和 AI 回答不自动跳转。

## 2. 工作职责与暂定承载

以下是当前工作职责的划分，导航数量与页面对应关系继续讨论。可按实际工作模式拆分、合并或重命名，避免用原四标签限制后续设计。

| 工作职责 | 主要对象 | 初步工作模式 | 调度设计任务 |
| --- | --- | --- | --- |
| 故事总控与来源 | 可编辑故事正文、留存的导入原稿、原文片段、忠实图谱、节奏要求、产物覆盖与项目进度 | 项目左侧切换原文／片段视图，选择故事范围并与当前任务联动；切分／裁减任务在右侧画布处理片段；支持 AI 提问 | D03 |
| 剧本与分镜制作 | 片段对应的剧本、多场分镜、人物和场景分配、素材输入、镜头衔接、视频片段 | 根据原文片段改编剧本 → 创建分镜并细化资源绑定 → 素材就绪后生成片段 | D04、D05a、D05b、D06a |
| 素材管理 | 生成条件、参考输入、任务结果及人物／服装／场景等资源版本 | 生成或提供素材 → 比较和修改结果 → 选用准确版本；使用位置作为辅助信息 | D05c |
| 成片剪辑与交付 | 已审核镜头片段、剪辑实例、多轨时间轴、固定交付版本 | 左侧按故事来源浏览资源，右侧全尺寸剪辑组件中选用、剪辑、后处理，再确认同一版本并发布／导出 | D06b、D06c、D07 |

故事拥有原文片段结构、原文对应关系与节奏要求；制作拥有剧本、分镜、资源分配与镜头衔接。原始故事对应多个故事片段，每个故事片段对应一个剧本，剧本对应多个分镜，分镜根据绑定资源生成视频片段，成片通过选择和剪辑引用这些视频片段。图谱忠实记录原文对象、关系与出处，未明确的信息保留不确定性，不承担额外的叙事创作。成片允许片段重排、重复取用和交叉编排，不反写制作中的镜头结构；每次取用是独立剪辑实例。

资源从剧本开始建立引用，随分镜逐渐细化；同一人物或场景的共用关系保留。细化内容不要求直接连回原文，其资产或制作对象的归属与引用继续记录；哪些内容属于细化、哪些需要原文对应关系，在具体流程中再定。素材负责提供、生成和修改资源；正式镜头生成使用就绪的准确版本。提示词随生成过程保存，不成为项目主层级。用户切换片段时画布跟随，后台任务完成不自动抢占当前画布。

故事总控默认按原文顺序组织片段，分别呈现产物数量与原文覆盖程度；两者不相互代替。自然语言查询读取项目状态并可定位相关片段。用户调整尚未生成视频的片段时，相关剧本和分镜标记为待更新；共用资产及已有视频的原文关联继续保留。节奏调整在故事空间表达意图，由后续制作环节落实；具体变更、覆盖计算及交互规则继续讨论。

以上为最新职责结论；现有只读框架及适配模型的迁移另行安排，不扩大当前 F0–F4 的实现范围。

## 3. 状态与调度的共同边界

- 归属树是唯一业务权威；空间标签与画布只展示同一套对象。镜头仍属于场，服装仍属于人物；版本切换不复制节点。
- 当前空间至多一个正在查看的对象；范围多选是另一种显式状态，不能冒充审核。各空间可记住视野与返回上下文，具体保存粒度待 D01／D02 确定。
- 自由摆卡、平移、缩放属于视图偏好；结构编辑和引用采用有明确目标与提交边界，不从坐标自动推断父级、顺序或版本。
- 素材关系表示准确版本的真实使用位置；场计划、镜头绑定、历史发布分别展示。素材到使用位置、使用位置到素材均能返回原上下文。
- 多项输入直接记录在镜头分配中：资源类型、用途与作用对象分别记录。人物／服装／场景／动作及运镜参考使用同一套可编辑输入列表，不暴露制作组合实体。默认不显示素材连线，点击镜头展开准确关系，再次点击收起，换镜头时切换局部关系；不累积全局网。镜头顺序可用轻量衔接线常驻表达。
- 创建任务时冻结目标范围、输入版本与依赖；结果归属发起对象及对应版本。后台完成不抢焦点，迟到结果不覆盖当前版本；具体队列与结果界面由 D06 设计。
- 任务队列属于项目，独立于当前查看的片段。切换片段或标签不取消、重启或重新归属已有任务；结果仍回到发起它的片段和对象。队列项可定位原片段、任务对应的工作画布及结果，方便主动找回；具体列表展示继续设计。
- 保存、确认、生成、采用、发布分开。任务成功不表示作者审核通过，采用新素材版本不自动改写已有引用，历史发布不因当前树移动而变化。
- 剪辑实例固定源镜头片段版本与入／出点，并记录轨道、位置、速度、声音和效果。发布与导出绑定同一个确认的剪辑版本及输出规格；重试交付不重新采用草稿或重新生成镜头。
- 亮色延续当前工作台，暗色延续主页；按钮与表单共享语义和几何规格。详细卡片与动效在工作模式明确后收敛。

## 4. 放弃的布局约束与保留的能力

旧三列页面堆叠、常驻完整项目树、左侧工具轨、独立版本工具、独立「章节编排」方案和旧 author 页面结构不再作为新设计约束。最新设计由项目级故事来源区、主体任务画布与按需上下文区域构成；左侧正文与来源对照是用户新提出的工作内容。准确路径、任务恢复、版本数据和引用能力保留。制作、素材不以单场选择限制画布。

正式归属、原文保护、素材规范、变更影响、发布快照和服务端校验仍依照[设计规范](design-spec.md)。布局可以重做，不能用前端卡片摆放替代这些契约。

## 6. 项目入口页

入口从「原作导入与故事市场」调整为「查看他人发布项目与新建项目」。浏览对象为公开项目，一个项目可以包含多个已发布成片；新建项目作为固定主操作。原文添加与切分属于项目内的故事总控。

- **主体**：公开项目列表，展示封面、项目名称、创作者与简要介绍；点击后查看该项目公开介绍和已发布成片。公开卡片按项目组织，不将同一项目的多个成片拆成多个项目卡片。
- **主操作**：顶栏保留统一的「新建项目」按钮；先建立项目，再进入故事总控添加原始故事。项目创建不会从公开项目卡片点击隐式触发。
- **个人项目入口**：暂定以同级「我的项目」入口恢复已有项目，不把草稿混入公开列表；位置与展示细节待讨论。
- **公开边界**：入口展示已发布项目内容。原文、图谱、剧本、分镜与资产是否公开另行讨论，不因项目发布默认全部公开。
- **空状态**：没有公开项目时仍能新建自己的项目；公开列表为空与用户没有项目是两个独立状态。
- **视觉**：双主题沿用整站配色，取消大幅导入宣传区和重复导入按钮。项目封面成为浏览主体，统一控件几何规格、主次动作与返回路径。

当前仅提供入口布局和浏览／创建路径的讨论稿；命名、公开内容范围、新建细节、登录与权限及业务接口仍待讨论，不宣称产品逻辑已实现。展示稿位于同一对话的项目入口设计预览。

## 7. 故事总控：连续原文与荧光片段

### 7.1 两种来源视图

- **原文**：以优质阅读体验连续展示当前故事全文，保留正文原有段落和换行。这里的「不分段」指不按制作片段切成独立阅读卡片；不插入片段标题、编号、进度、分隔线或操作块。片段边界由荧光区域表达，正文行长、字距、行距和留白服务于阅读。
- **故事片段**：根据用户／AI 实际建立的片段动态呈现名称、正文摘要和真实进度，按来源顺序组织。片段可点击跳转，不是写死的示例卡片；新建、拆合或调整后列表与原文荧光区域同步。
- 两种视图共用同一正文版本、稳定片段 ID 和来源范围。未分配文字始终保留在原文中，可继续阅读和划选；切换视图不复制故事，也不重置阅读位置。
- 前台「原文」是全文来源视图的名称，初始内容来自导入原稿；修改后的当前故事正文形成新版本，导入原稿仍作为历史依据留存，不被原地覆盖。不增加第二套常驻稿件栏或独立版本工具。

### 7.2 一个连续荧光区域对应一个故事片段

荧光区域是片段的完整来源范围。它可以跨正文原有段落，但仍是一块连续范围；不因为剧本中有动作、对白等多个目标，就把来源拆成多个零散荧光标记。

| 操作或情况 | 确定行为 |
| --- | --- |
| 在未分配原文中划选 | 得到一个连续、非空的临时选区，显示建立候选或取消的入口 |
| 建立候选片段 | 分配稳定片段 ID，保存正文版本与精确范围；荧光区域和动态片段列表同时出现，进入切分／裁减上下文 |
| 确认片段 | 独立确认操作，候选不因建立、浏览或 AI 返回而自动确认 |
| 点击已有荧光区域／片段项 | 跳转并恢复对应片段的工作上下文，不重复创建片段 |
| 空选区或多块不连续选择 | 不建立片段；一个片段的来源必须是连续且非空的范围 |
| 重复选择、部分相交或完全包含已有区域 | 阻止直接新建，指出冲突片段并提供定位；不静默裁掉重叠文字、覆盖边界或新增重复片段 |
| 新旧区域仅边界相接 | 允许，双方不占用同一文字；不强制留下空白间隔 |
| 取消临时选区 | 不改变正文、既有区域或确认状态 |

已保存候选和已确认片段都参与范围冲突检查。调整边界、拆分和合并在明确的编辑动作中预览新范围及受影响对象；提交时作为一组变更校验，不能借重新划选绕过已有归属。AI 提出的候选同样遵守非空、连续、不重叠规则。

阅读中的临时划选和逐个建立候选允许存在未分配正文。提交完整切分方案时，再针对明确的制作范围检查来源顺序和覆盖，并明确呈现漏覆盖、裁减或范围外内容；完整方案校验与候选校验分开，不因全文尚未切完就阻止第一次划选。

### 7.3 片段跳转、进度与持续任务

- 普通制作任务中，切换片段恢复目标片段的工作状态、所选对象、对应步骤和画布视野。来源视图、阅读位置与各片段上下文保留；片段列表从项目数据生成。
- 成片采用项目级剪辑上下文。点击左侧片段／资源用于定位来源、浏览或预览相关素材，不替换当前剪辑、不清空时间轴；只有明确插入才创建剪辑实例。
- 原排队／执行任务独立持续，切换片段或标签不取消、重启或改变归属。任务冻结发起片段、对象、正文及输入版本；完成只更新原目标，不抢占当前视图。
- 项目任务队列能主动定位任务原片段、对应工作区和结果。返回恢复工作位置，不再发起一次任务。
- 确认、剧本、分镜、资产、视频、成片和发布分别显示真实状态。产物数量与原文覆盖分开统计，进度信息放在片段视图和对象上下文，不打断原文阅读。

### 7.4 正文和范围修改

当前故事支持编辑、增补与片段边界调整。保存正文、确认片段、生成、采用和发布是不同动作。新正文版本需要同步或复核来源范围；失效映射标记待复核，不能仅挪动高亮或按相同文字搜索后宣称已恢复。

相关剧本和分镜标记待更新，共用资产保留真实归属；已有视频、已确认剪辑与历史发布保留生成／采用时的正文和输入版本，不静默替换。部分已生成片段如何拆合、AI 写入的预览与采用、映射冲突的人工修正仍由 D03 细化。

## 8. 大标签的开放方向

原四个大标签不固定。大标签承载工作任务，片段范围作为可恢复上下文；具体数量、名称与层级继续根据工作方式设计。

此前「每个确认片段打开一个大标签」仍是候选方案，不必通过持续增加标签表达片段。成片保留项目级剪辑上下文，资产保留项目级共用归属；片段进入和返回的视觉呈现继续优化。交互稿中的切分、剧本、分镜、资产、成片是职责示例，不将这五个名字或数量直接作为开发契约。

现有四标签框架与历史展示记录不因本轮设计确认自动重构，迁移在下一阶段安排。

## 9. 不同任务中的来源联动

| 当前任务 | 左侧故事来源区 | 右侧主要工作 | 连线表达 |
| --- | --- | --- | --- |
| 切分／裁减 | 连续阅读、划出新区域，或点击已有片段 | 无限画布中的候选片段、边界调整、拆合与裁减 | 完整来源区域到片段，保留出处 |
| 剧本 | 点击一块完整片段荧光区域，对照人物动作和语言 | 无限画布中的剧本动作、对白及改编对象 | 从实际荧光区域边缘一个点出线，经共同主干分支到相关对象 |
| 分镜 | 当前片段来源与剧本依据 | 无限画布中的场、镜头和输入引用 | 当前选择的实际来源／引用，不铺满全项目连线 |
| 资产 | 片段来源及原文人物、服装、场景、道具等出现位置 | 无限画布中的资源需求、实际项目资产与版本 | 原文出现位置到实际资产；同一资产可有多处出处 |
| 成片 | 故事来源／片段列表作为资源区，按来源浏览、预览和选用视频 | 剪辑组件铺满右侧主工作区，包含预览与多轨时间轴；不采用无限画布 | 保留来源引用，用资源定位和属性追溯，不将时间轴对象当自由画布卡片 |

- **局部双向关系**：选择来源范围时突出相关画布对象；选择画布对象时定位其来源。连线只展开当前选择的关系，避免全文到全部产物的全局网。关闭连线不删除对应关系，浏览和修改关系分开。
- **剧本统一出线**：来源起点位于当前完整荧光区域实际渲染的边缘，一个起点和共同主干再延伸到动作、对白等多个剧本对象。起点不放在侧栏外沿、片段标题或凭空设置的端口，也不为动作、对白分别制造来源区域。目标内的细粒度文本映射可保留，但不改变片段的整块来源表达。
- **几何与归属分开**：原文滚动、文字换行、栏宽调整，以及画布对象拖动、平移、缩放，都按当前可见的文字区域和目标对象重算线的位置，不修改源范围、业务归属或引用。区域跨行仍只有一个来源起点；长区域起点选择和离屏提示的视觉细节继续优化。
- **共用资产与细化边界**：同一对象的多处原文出现可以关联同一实际项目资产及准确版本。资产词语／出现位置是片段范围内的次级引用，不将每个出现位置变成新的故事片段，不因跨片段使用而复制资产归属。细化内容保留其资产／制作对象归属与引用，是否需直接出处在对应流程中讨论。正式生成需求与镜头输入仍从剧本开始绑定并逐层细化。
- **来源与产物状态分开**：原文提到了某项资产，不表示素材已经生产；有剧本对应，不表示已有视频。显示对应对象的实际状态，不从连线存在推断制作完成。
- **变化可追溯**：当前故事正文改变时保留历史产物所依据的文本与关系，提示受影响内容待更新；来源查看与局部连线浏览不改写数据，执行任务和结果归属继续保持。

成片中，同一个源视频可以多次插入时间轴，各次使用是独立剪辑实例，保留源片段、镜头和媒体版本；删除或重排实例不删除资源、不反写镜头顺序。属性按需展开或覆盖显示，收起后完整剪辑组件继续占满主工作区，具体尺寸与工具排列由 D06b 优化。

## 10. 对象属性与当前步骤对话

- **所选项目对象的属性**：属性面板跟随实际选中项，展示稳定 ID、真实归属、来源、准确版本和实际状态，具体字段随对象类型变化。共享资产归属项目中的对应资产位置；剪辑实例归属当前剪辑并保留源片段／镜头／媒体版本。不以当前标签、片段筛选或画布位置冒充对象归属。
- **每个步骤都有对话入口**：切分／裁减、剧本、分镜、资产的无限画布底部均固定一个可自由提问的输入区；成片剪辑工作区也保留同等入口。入口处于工作区界面层，不作为随画布平移、缩放的节点；不遮住主要画布操作或时间轴。
- **无需标明 Agent 名称**：不要求显式显示 Agent、模型或角色名字，也无需机器人图标作为入口身份。用当前步骤、片段和选中对象表达上下文，用户直接提问。
- **上下文与历史可恢复**：对话绑定项目、当前步骤、片段／选区、所选对象和对应版本。切换步骤或片段后加载相应历史，回到原上下文可继续对话；全项目问题显式使用全项目范围，不能把未展示的筛选默认为问题范围。
- **建议与执行分开**：回答可提供原文出处、对象定位、候选切分或改写建议；问答、查看建议和建立候选不自动确认、生成、采用或发布。真实写入与任务提交仍有明确目标和动作。后台回答和任务完成不抢焦点。

## 11. 精确范围契约与后续工程

交互规则已经确认；正式字段、接口和迁移方案需要在 D03 及下一阶段开发中补齐，不能将设计稿的本地状态当成后端能力。

- 每个片段至少需要项目 ID、稳定片段 ID、来源正文 ID／版本、精确起止边界及候选／确认状态。范围采用半开区间表达，等价于 `[start, end)`；相邻区间可共享边界，重叠判定为 `a.start < b.end && b.start < a.end`。字符计数单位、换行规范和跨端换算在接口契约中统一，不能依赖 DOM 节点序号、显示段号或画布坐标。
- 服务端校验版本存在且匹配、边界合法、连续非空和片段范围不重叠；前端即时冲突反馈与服务端最终校验一致。正文或边界并发变化时返回明确冲突，不悄悄挪动范围。拆合／多片段变更整体校验并提交，稳定身份与继承关系另行定义。
- **现有代码边界**：`backend/segments.py` 仍使用段落级 `source_refs`（P 编号），已有校验涉及引用合法性、重复、顺序及相邻片段的重叠／间隙，并有旧流程的数量预算限制；尚无精确到文字选区的正式范围契约。不能把段落引用当成字符范围，也不能宣称当前校验已完整保证首尾覆盖。
- 新范围模型需要版本化迁移与旧 `source_refs` 的兼容映射，保留历史文本、片段及产物依据。完整方案的来源顺序、首尾覆盖和裁减／范围外标记单独验收；不把旧计算窗口的数量限制当成整部故事的永久产品上限。
- 剧本对象关系、资产出现引用、所选对象属性和对话上下文都复用稳定业务 ID 与正文版本。连线显示几何、阅读位置和画布视野单独作为视图状态保存，不能维护另一套可写来源。

后续任务和验收点已同步到[设计任务骨架](design-task-skeleton.md)及[框架后的工程安排](implementation-plan.md#7-本轮确认设计与后续工程安排)。仍待优化的内容包括阅读栏宽度与收起、长区域／离屏连线、正文编辑与映射复核、未保存内容处理、任务队列呈现、键盘／触屏等价交互及导航命名。

本轮设计依据为[来源工作台交互稿](../../../prototypes/source-studio.html)。已走查整块区域统一出线、原文划选建候选、重复／相交冲突、相接边界、片段跳转、动态列表及成片布局；交互稿仅用于设计确认，示例资源、对话和本地状态不代表真实生成、保存或剪辑内核已经接入。
