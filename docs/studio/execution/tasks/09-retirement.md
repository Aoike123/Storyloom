# 旧产品退役卡

版本：2.1 · 当前任务定义。顺序与派发规则见[实施计划](../implementation-plan.md)，实际状态只见[账本](../acceptance-ledger.json)。

路径以[项目结构](../../architecture/project-structure.md)为准。任务族父卡只汇总，不派发；执行器收到下面一张单行为子卡及已冻结接口。主模型派发时收窄白名单至至多3个实现文件加直接验证，并填入准确命令/操作与负向情形。

用户已授权删除旧版代码。以下清单审定和验收由主模型执行，不是额外的用户许可流程。

## RETIRE-01 · 禁止新业务依赖旧业务的检查

- 执行者：主模型设规则并冻结逐文件退役清单，轻量模型实现依赖检查。依赖：ROOT-05、BASE-01。
- 白名单：一个依赖检查脚本、新代码测试规则及相应测试；清单由主模型维护。
- 实施：检查新模块的直接/间接旧业务imports、旧API字符串、旧Task/Record阶段写入；明确允许基础设施白名单。主模型按实施HEAD逐文件审定待删除/解耦/提取项、引用方与复验范围，并记录于architecture中的退役清单；ROOT-05分类盘点不能代替该清单。
- 验收：新业务调用旧作者服务会失败，纯账号/数据库连接/协议工具可通过；历史文档不误判为运行依赖；退役清单带准确基线及逐文件动作，未冻结前退役子卡不可ready。
- 产品规则：R01, R11，见[产品规范](../../product/product-spec.md)。
