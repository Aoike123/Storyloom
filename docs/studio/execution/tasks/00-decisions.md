# 主模型准备卡

版本：2.1 · 当前任务定义。顺序与派发规则见[实施计划](../implementation-plan.md)，实际状态只见[账本](../acceptance-ledger.json)。

路径以[项目结构](../../architecture/project-structure.md)为准。任务族父卡只汇总，不派发；执行器收到下面一张单行为子卡及已冻结接口。主模型派发时收窄白名单至至多3个实现文件加直接验证，并填入准确命令/操作与负向情形。

## ROOT-01 · 固定隔离重构基线

- 执行者：主模型。依赖：无。范围：Git/文档保护/运行目录。
- 动作：记录主目录HEAD、3001实际进程、依赖运行时；保护未提交文档；选择可写重构分支/checkout和独立测试端口，避免修改正在使用的旧生产页面。
- 验收：账本有绝对实施目录/分支/HEAD/前后端端口/启动命令；无需跨目录拼代码；没有reset --hard、覆盖本地修改或占用3001测试。
- 产品规则：R01, R11，见[产品规范](../../product/product-spec.md)。

## ROOT-02 · 冻结新schema、API与状态附录

- 执行者：主模型。依赖：ROOT-01。
- 动作：把契约各聚合落实为表/字段/外键/唯一性/CAS和状态转换；逐命令写请求/响应/错误及影响清单；依据R规则重新定义业务依赖和审核，不继承旧workflow作为标准；定义统一ObjectRef和领域查询DTO。
- 验收：DB/SOURCE/VIEW/SCRIPT/SHOT/ASSET所需类型、路由、并发与采用含义明确；没有万能patch、旧stage/Gxx/Pxxx、第二套可写归属树。未明确的命令不派发。
- 产品规则：R01, R11，见[产品规范](../../product/product-spec.md)。

## ROOT-03 · 定一个真实剪辑内核适配方案

- 执行者：主模型。依赖：ROOT-01、ROOT-02。
- 动作：核对本地媒体能力和候选正式源代码，必要时查官方资料；用两段本地时间码视频及音频做PoC；冻结manifest、支持操作、预览/导出、格式、依赖许可证、取消/失败/重试。
- 验收：同manifest能证明预览与导出切点/时长/声音一致；输出是真文件；没有让轻量模型挑库或图标模拟播放。
- 产品规则：R01, R11，见[产品规范](../../product/product-spec.md)。

## ROOT-04 · 冻结新任务及agent adapter

- 执行者：主模型。依赖：ROOT-02。
- 动作：从新产品操作重建每种命令/异步任务/提案的目标、触发、前置、用户确认点和恢复表，再给每个job kind确定输入/输出schema、供应商协议、队列/lease/重试边界、实际请求元数据、成本确认；定义会话范围和proposal白名单。
- 验收：StudioJob是唯一新状态权威；提取的client无旧Record/Task/阶段依赖；回答不直接写业务；不可确定的供应商提交不能自动重复收费调用；新流程不受旧节点名、prompt payload或旧测试断言约束。
- 产品规则：R01, R11，见[产品规范](../../product/product-spec.md)。

## ROOT-05 · 旧代码退役依赖清单

- 执行者：轻量模型只读盘点，主模型验收。依赖：无。
- 动作：检查app.py路由、前端import、旧worker/生成/观看耦合，分类旧产品代码与可提取基础设施；列退役顺序。
- 验收：清单明确authors.py/creative/director不是孤立UI，删除前新业务需解除全部依赖。清单只用于删除/提取，不用于功能兼容或迁移。
- 产品规则：R01, R11，见[产品规范](../../product/product-spec.md)。
