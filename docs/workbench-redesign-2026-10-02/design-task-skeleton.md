# 画布工作台设计任务骨架

版本：0.8 · 2026-10-03 · 状态：D00 完成，大结构基本认可；开发计划仅到框架，细节待讨论

本文件是设计讨论入口。空间方向见[画布优先设计方向](canvas-design-direction.md)，领域约束见[设计规范](design-spec.md)，正式开发安排见[框架开发计划](implementation-plan.md)。开发范围只到框架验收；D03–D08 与下文业务边界保留为讨论索引，具体操作尚未确认，不作为实施排期。

## 1. 本轮边界与推进方式

- 故事、制作、素材以无限画布为主体；成片采用剪辑时间轴。四个固定入口移到顶部标签，内部对象、分组与共用关系按当前流程组织。
- 删除左侧常驻工具栏，画布直接占据主内容区域；右侧保留按需上下文区域，删除独立版本入口。旧三列页面堆叠与独立「章节编排」布局不作为约束。
- 每次只推进一个明确设计任务，产出对应规范与必要的交互稿；先回答工作方式，再细化视觉。完成结论回填现有规范，不为每个任务新建一套重复文档。
- 当前 D00 完成，D01 已有样式展示但交互规范尚未定稿；制作先整齐排列多场、多镜头，素材突出生成入口，不展开全部生产流程。
- 制作和素材默认显示整个画布，不设置场次选择器或常驻图层索引。场是画布上的分组，用户可自由摆放对象。
- 「骨架完成」只表示方向、边界、任务和依赖清楚；「可开发」要求该任务的开放问题已回答、关键动作可走查。设计状态与产品实现状态分别记录。

## 3. 各任务的设计边界

### D00 · 设计骨架

- **交付**：空间骨架、四个空间的职责表、任务列表、共同调度模板、下一步范围。
- **完成依据**：明确哪些是固定入口、哪些属于画布对象、哪些工具按需打开；旧三列方向已被替代，其他任务均保留待设计状态。
- **本轮不展开**：全部节点样式、详细手势、真实排程、各类表单、接口改造及全站验收。

### D01 · 工作台壳与顶部导航

- **范围**：精简项目顶栏、四个空间标签、主体画布、右侧上下文容器与面板开合；不设左栏或独立版本工具。
- **开放问题**：选中即显示摘要还是主动打开编辑；面板如何避免遮住当前对象；切换空间、引用跳转与返回各恢复什么上下文；未保存编辑如何处理。
- **产出**：一张主布局骨架、空间切换和跨空间返回路径、面板状态表。只展示代表性对象，不画完所有业务表单。
- **出口**：画布占主体，定位与编辑能找到，顶部保留四个固定入口，前后步骤用线性流程表达；当前对象、查看版本、返回来源关系明确。

### D02 · 画布交互基础

- **范围**：选择、框选、视野移动、缩放、适配、定位、卡片排布、容器展开／进入、拖拽反馈、键盘与触屏等价操作。
- **开放问题**：普通拖动与结构移动如何区别；什么情况下允许跨组投放；长作品如何聚合和分层；小地图或按需大纲是否必要；编辑与画布快捷键如何避让。
- **产出**：指针／键盘行为表、拖拽状态图、视图状态与业务状态边界。
- **出口**：用户能辨认当前模式与投放结果；自由摆卡不改变归属、顺序或引用；关键动作有不用精细拖拽的入口。

### D03 · 故事与预处理画布

- **范围**：原文及原文章节、调整草稿、采用稿、处理范围、精简／扩写／节奏目标、差异与来源追溯。
- **开放问题**：阅读长文如何进入；多个调整方案如何比较；新增与删减如何显示；采用新稿怎样查看已制作内容的影响。
- **产出**：故事画布工作模式，以及「范围 → 预览 → 保存 → 采用」路径和失败／过期结果状态。
- **出口**：原文始终保留；保存与采用分开；只处理明确范围，采用前能看清变更及影响。

### D04 · 剧本与场次编排画布

- **范围**：可选篇章／集、场的层级，剧情、台词、叙事目的与原文来源；拆分、合并、重排、移动与局部聚焦。故事输出剧本依据，制作承担分镜创建。
- **开放问题**：长剧本的阅读和编辑方式；自由布局和正式排序如何区别；采用新剧本对已有分镜的影响怎样复核；短故事如何省略中间层。
- **产出**：短故事与长故事各一条结构操作路径，结构变更预览、合法投放与衔接复核规则。
- **出口**：对象归属与叙事顺序可读；变更保留稳定 ID；原文章节与制作集不被合并；局部聚焦可返回原视野。

### D05 · 分镜设计与素材生成

拆分为独立设计任务，按顺序定稿，均为待设计：

- **D05a · 分镜创建与衔接**：根据采用剧本的剧情和台词创建镜头，编辑画面、人物行动、构图及前后镜头衔接。默认在无限画布中按场排列多镜头，设计新增、拆合、重排与来源复核。
- **D05b · 镜头素材分配**：按用途与作用对象分配人物、服装、物理场景及参考输入；允许用户增删、替换和调整归属，生成素材需求。产出逐镜头及批量编辑、影响预览与采用规则。
- **D05c · 素材生成与版本**：围绕生成条件、参考输入、生成任务、结果比较和版本选用设计；支持上传与修改。使用位置是辅助信息，不作为素材页主体，不引入组合对象。

开放问题包括批量分配与逐镜头调整的关系、人物与服装的目标一致性、参考视频片段范围、计划引用与实际制作输入的区分。新资源类型沿用同一套「用途／作用对象／资源版本」输入行，不增加一级导航。

出口：制作以剧本驱动分镜，素材以生成和版本结果为重点；两处不设置场次筛选器。素材只有一份归属；素材准备先于正式镜头生成；点击镜头展开准确素材连线，再点同一镜头收起。关系可编辑，浏览与自由摆卡不隐式修改关系。

### D06 · 镜头生成与剪辑

拆分为独立设计任务，均为待设计：

- **D06a · 生成与审核**：选定就绪镜头，冻结实际输入，排队、生成、核对结果并审核；通过审核的片段进入镜头库。任务完成不等于作者采用，迟到结果不覆盖当前版本。
- **D06b · 剪辑与后处理**：从镜头库自由选择片段，重排、重复取用、裁切并组合多轨画面、对白、环境声、音乐与字幕。剪辑实例记录源版本与入／出点，不改变故事的镜头顺序。
- **D06c · 开源内核接入**：定义独立时间轴模型、预览与导出适配边界，完成候选内核的小范围接入评估；不在样式展示阶段安装或集成内核。

产出分别为任务生命周期与结果落点、镜头库和时间轴操作路径、内核适配契约。蒙太奇由片段排列、时长与声画关系构成，交叉剪辑、匹配剪辑、J-cut／L-cut应落到明确的时间轴操作，而不是只增加效果按钮。

### D07 · 发布、导出与历史版本

- **范围**：成片中的确认版本、媒体就绪检查、发布与导出状态、历史回看。
- **开放问题**：确认版本如何固定；发布和文件导出的状态如何分别显示与重试；已有版本的修订怎样创建新版本。
- **产出**：确认剪辑版本、发布／导出与历史回看的路径。
- **出口**：发布和导出绑定同一确认的时间轴及输出规格；允许部分交付失败后单独重试；草稿修改不改变已确认或已发布版本。

### D08 · 视觉、双主题与动效收敛

- **范围**：画布背景、卡片层级、容器与连线、统一按钮、浮动工具与编辑面板，选中／待审核／失败反馈，窄屏与触屏策略、减弱动态偏好。主页、市场和导入入口与工作台采用同一组件基线。
- **开放问题**：不同缩放层级显示什么；跨空间与定位动效怎样解释方向；触屏怎样保留画布优势；氛围层如何避免硬切割。
- **产出**：组件与状态规范、完整明暗稿、必要的动效示例、关键小屏取舍。
- **出口**：亮色延续当前工作台，暗色延续主页；尺寸和按钮行为一致；没有混搭表面、遮挡主操作或依赖颜色才可识别的状态。

## 4. 每个画布必须回答的调度模板

这里的「调度」同时包括交互分派和制作任务生命周期，不能只设计拖拽手势。D03–D07 定稿时分别填写下表；当前只列问题，不预设完整答案。

| 项目 | 必须回答 |
| --- | --- |
| 对象与默认范围 | 初次进入显示什么；节点归属、版本与当前工作范围如何表达？ |
| 模式与手势 | 点击、双击、拖动节点、拖动空白、框选、缩放分别做什么；如何退出模式？ |
| 容纳与引用 | 投入容器、自由摆卡、建立引用的区别；合法目标与取消方式是什么？ |
| 操作与输入 | 哪些动作直接查看，哪些编辑结构／引用，哪些创建任务；提交时冻结哪些对象、版本和输入？ |
| 排队与结果 | 排队、运行、失败、待核实、输入过期在哪里显示；结果归属于哪个对象和版本？ |
| 审核与采用 | 保存、任务完成、作者确认、采用、发布如何分别表达；影响范围在哪里检查？ |
| 定位与返回 | 跨空间查看引用后如何回来；每个空间保存哪些选择、视野、展开和查看版本？ |
| 规模与恢复 | 空、长作品、移除对象、冲突及断网如何恢复；键盘与触屏的等价路径是什么？ |

画布位置属于视图偏好；归属、叙事顺序、素材绑定属于业务状态。直接编辑可以在画布发生，但必须让操作类型、目标、预览和提交结果可辨认，不强制把所有写入都塞进同一种侧栏。

## 5. 本阶段的走查与交付

- 骨架只检查方向一致、任务不漏、依赖可执行、文档链接有效，不运行生产测试或逐断点截图矩阵。
- 每个后续任务只走查它的关键路径与未决风险；需要交互稿时再做小范围原型，不在本轮完成全套 UI。
- 开发阶段按实际改动执行必要检查；已有实施验收清单保留为后续依据，不变成每轮设计的重复测试。
- 交付描述明确区分「已搭骨架」「设计可开发」「产品已实现」。当前只有第一项完成。

## 6. 样式展示记录 · 2026-10-03

预览为 `storyloom-canvas-shell`。当前是 D01 的样式骨架，未接生产接口，不标记完整 D01 或其他设计任务完成。

- **主体空间**：64px 项目顶栏、50px 顶部标签；左侧工具轨已删除，右侧约 56px 上下文工具轨，属性约 288px，可展开和收起。右侧不设独立版本入口。故事、制作、素材采用无限画布；成片保留剪辑工作区示意。
- **四个大标签**：故事、制作、素材、成片。故事沿「故事处理 → 剧本编排」推进；制作以剧本和台词创建分镜。素材输入是镜头设计的一部分，不再单独做一个只读引用步骤。
- **稳定上下文**：顶部切换由用户主动操作；查看素材、镜头、搜索结果或使用位置在当前标签的右侧展开。不会为查看一条引用自动跳标签。正式的返回、未保存编辑与焦点规则待 D01。
- **剧本编排**：篇章和场组织剧情、台词与来源；分镜在制作画布创建和编排。
- **制作画布**：三组场景各横排三个镜头，组标题展示本场台词，细线表达镜头顺序。支持自由拖动与整齐排列；右侧展示剧本来源、画面意图、衔接与素材输入。无左侧场次选择器。
- **素材画布**：独立素材按网格排列，突出生成新版本；生成条件中提供名称、类型、画面要求和参考版本。占位为待生成或待提供，不冒充就绪媒体。
- **局部关系**：点击镜头展开引用，再点收起；输入可在右侧增删或换版本，共用统计随示例分配更新。当前编辑仅为原型状态，正式校验、撤销、保存与影响采用待设计。
- **成片**：镜头库、预览占位、多轨时间轴与发布／导出位置。时间轴为编排示意，当前没有真实可播放片段，剪辑和交付动作尚未接入。
- **统一组件**：节点圆角默认 16px；按钮圆角 8px，主按钮最小高 44px。主题、属性与视野工具共享语义色。平移、缩放、自由摆卡、查看详情和连线开合可体验；拖动仅改变视图。样式稿中的业务表单和点击是讨论素材，不直接进入本期框架实现。

本轮只做脚本语法检查与代表性的浏览器走查，不执行全量测试、逐断点截图矩阵或等待生产任务。

## 7. 镜头与素材的多对多关系

素材分配直接记录在镜头上。通用输入行包含「用途／作用对象／准确资源版本」，参考视频还包含片段范围。用户查看与编辑的对象是镜头及素材，无须额外创建、命名或维护制作组合。

示例镜头包含以下输入；多个人物、多套服装、道具或声音继续增加输入行，不扩展导航结构：

| 用途 | 作用对象 | 固定输入 |
| --- | --- | --- |
| 人物身份 | 演员：林遥 | 林遥身份 v1 |
| 人物服装 | 同一演员：林遥 | 灰色外套 v1 |
| 空间环境 | 当前场 | 旧站台 v1 |
| 动作参考 | 演员：林遥 | 停步与转身视频 v1，00:03–00:07 |
| 运镜参考 | 当前镜头 | 缓慢推近视频 v1，00:01–00:04 |

- **点击开合**：默认无连线。点击镜头只展开这一镜头的准确素材引用；再次点击同一镜头收起，点击另一个镜头切换展示，不累积全项目网。
- **详情与画布分工**：画布展示镜头到资源的关系，右侧列出用途、作用对象、版本与视频区间；同一资源被多项输入使用时，画布只画一条线，右侧保留各项用途。
- **归属与使用分开**：服装属于人物，镜头引用场景资源；人物出现在哪个场不改变资产归属。动作参考指向演员，运镜参考指向镜头，不从文件类型推断作用对象。
- **唯一数据来源**：故事维护剧本和场次，制作维护镜头结构与素材分配，素材负责资源生成及版本并查询这些引用。资源改版不自动改变已分配版本；镜头替换输入有独立的影响预览与采用边界。
- **任务冻结**：生成前解析最终输入并冻结镜头、资源与媒体版本、片段范围和来源；后台可优化复用，但用户不必管理新的组合实体。
- **双向共用**：素材详情按场列出实际使用它的镜头；镜头详情列出准确资源。计划引用、生成时输入与历史发布分别查询，替换后的旧资源不计入当前实际使用。
- **可扩展契约**：输入至少包含用途标识、稳定作用对象 ID、资源 ID／版本、可选片段范围与来源；校验服装所属人物、用途兼容性和参考视频边界。

样式骨架可体验单镜头输入增删和版本替换；领域兼容校验、批量编辑、影响预览、正式保存与采用规则留到 D05b。

## 8. 线性流程与成片边界

故事处理产生采用稿，剧本编排输出篇章、场、剧情和台词。制作依据剧本创建分镜，确定人物、服装、场景归属及镜头衔接，形成素材需求；素材负责生成或提供资源。素材就绪后制作生成并审核镜头片段。用户主动切换大标签，查看引用或任务完成不跳标签。

成片从已审核镜头库自由选取片段。一个镜头可多次出现在时间轴上，各剪辑实例独立记录位置、入／出点、速度、效果与声音；交叉编排不反写制作中的镜头结构。发布和导出固定同一份确认的剪辑版本，分别记录交付状态。

当前阶段不把所有步骤实现完：D01 先定稿导航和上下文，D05a／D05b／D05c 分开设计分镜创建、素材分配与素材生成，D06a／D06b／D06c 再分开设计片段生成审核、剪辑和内核接入。

## 9. 剪辑内核的初步选型

- **优先评估 [libopenshot](https://www.openshot.org/libopenshot/)**：官方提供 C++ 剪辑库与 Python 绑定，支持多轨、裁切、转场、关键帧、变速和音频处理。结合项目现有 Python 后端，适合作为服务端预览／渲染的首个候选；这是初步判断，尚未验证接入和性能。
- **备选 [MLT](https://www.mltframework.org/)**：官方定位为非线性剪辑的多轨音视频编排内核。D06c 在首候选不满足预览、效果或部署需求时，再评估这条路径。
- **可参考 [OpenCut](https://github.com/OpenCut-app/OpenCut)** 的完整剪辑应用布局；其核心能否独立复用需后续评估，不把整个应用直接当作已确定的可嵌入内核。

前端时间轴、Storyloom 的镜头版本与项目关系保留独立模型，由适配层转换为内核输入。预览、发布与导出共享确认的时间轴；D06c 只检查一条「片段裁切与重排 → 声画交错 → 预览 → 同版导出」路径，并核对依赖许可和实际媒体表现，不开展无范围的测试矩阵。
