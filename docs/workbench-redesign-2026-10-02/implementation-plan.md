# 工作台实施计划与验收清单

版本：1.2 · 2026-10-03 更新 · 状态：后续开发参考，旧布局条目待设计回填

设计基线：[叙间工作台设计规范](design-spec.md)。本文件安排实施顺序与交付证据，不包含已经完成新功能的声明。开发完成后，按本清单验收；不安排自动跟踪或未经请求的后台执行。

> **当前阶段**：先按[设计任务骨架](design-task-skeleton.md)逐项完成设计，当前仅 D00 完成、D01 待设计。空间方向已改为顶部标签、主体无限画布和按需工具，见[画布优先设计方向](canvas-design-direction.md)。下文的精简目录、常驻编辑列、两套工作视图及其界面验收项已被替代，需在对应设计定稿后更新，不按旧布局开发。本文件的领域契约和实现里程碑保留为后续参考，不在骨架阶段启动开发或执行测试矩阵。

## 1. 实施范围与工作方式

后续开发覆盖顶部空间与主体无限画布、按需编辑工具、故事预处理、可伸缩故事结构、素材共用关系、逐版本审核、制作调度和发布快照，按已定稿的设计任务分批实施。明暗双主题与按钮规则从第一批组件开始统一。

1.1 修正原先六个功能工作区平铺的设计：篇章／场／镜头具有真实父子关系；人物、服装、场景具有唯一归属，跨场共用以准确版本引用展示。1.2 进一步调整空间布局：用画布呈现制作结构，目录和对象编辑区辅助定位与操作；层级不再被限制为一列密集文件目录。两种视图共享唯一归属、选择和业务状态。实施顺序先解决归属和引用契约，再实现画布、双向定位及生产操作。

先完成数据与版本契约，再连接真实交互。每个里程碑独立可验收，不能以一个巨大页面替换现有工作台后再补状态逻辑。

开始开发前记录 Git 状态与已有行为，保留并单独识别已有改动，不把现有 UI 调整误当成本计划的实施结果。

M1、M2、M4 可以在契约确定后独立推进；它们共享版本字段、确认模型与组件规范。顺序依赖未满足时可以完成界面结构，但不能宣称真实流程已通。

### M0 · 基线、术语与迁移方案

**工作内容**

- 盘点 author、director、creative、preproduction、production 与 Task 的实际状态转换，不仅依赖页面阶段名或工作流元数据。
- 固定项目节点、原文、改编稿、结构、场、镜头、素材版本、绑定、确认、发布的契约；记录现有 ID／段号与新稳定 ID 的映射。
- 明确归属的唯一权威来源、允许的父子类型、稳定节点 ID、同级顺序与树版本。禁止循环、跨项目父级、重复归属；镜头所属场及服装所属人物与项目树一致。
- 定义按准确素材版本查询使用位置的契约，区分场级计划、镜头实际绑定与发布快照；计数由引用去重生成，不维护另一套前端关系数据。
- 确认新流程版本及兼容读取策略。旧流程不直接放宽全局校验来冒充长故事支持。
- 建立固定的本地验收数据：短故事、分章节故事、分集故事、多服装角色、已发布后修改、失败与结果不确定任务。

**出口标准**

归属树与跨分支引用分别可审查，非法归属写入被拒绝；旧项目读取、发布和任务恢复有兼容策略；验收样本可重复加载。尚未执行供应商付费任务也能验证接口与状态。

### M1 · 项目目录、画布、对象编辑器与设计系统

**工作内容**

- 统一双主题 token、四类按钮、表单、状态标签、对象导航、版本标签与可见焦点。
- 建立唯一归属树，以精简项目目录、主要结构画布和当前对象编辑区呈现故事、制作内容、共享素材和发布分支。画布按篇章组织场，场中展开镜头，取消独立的第二套场选择。
- 实现叙事画布与章节编排两种工作视图，统一 selected_node_id、expanded_node_ids、detail_tab、inspected_revision 和返回上下文；切换视图不复制业务状态。
- 实现画布缩放、视野移动、适配和定位，恢复视野偏好；视图坐标与 parent_id／order_key、引用及审核分别保存。缩放具有可读下限，长项目按范围进入或分层加载。
- 实现独立的展开／选择行为、真实面包屑、节点类型驱动的编辑区及局部页签。按屏幕尺寸检查节点点击范围；键盘焦点在画布中始终可见。
- 实现引用到素材、素材到场／镜头的双向定位和返回，展开目标祖先；刷新、前后导航、改名／移动与响应式切换后恢复准确上下文。
- 窄屏完整目录为可打开的独立导航区，选中后返回内容；画布改为按篇章排列的节点列表，先呈现当前对象与主动作。使用原生语义列表与按钮，或完整实现 ARIA 树的键盘契约。
- 总览突出当前待办；任务日志、原文与设置转为次级信息，不再同时平铺。
- 主页「浏览故事市场」使用页内锚点，导入使用统一独立页面；区块光晕和表面衔接重做。
- 整站文案以「故事」为通用类型；允许实际故事标签包含「微小说」，但不能把所有输入与制作单位限制为微小说。

**出口标准**

树中的实际父级与后端一致，展开、平移和缩放不改变业务状态，选择不审核／生成；目录、两种工作视图和对象区只有一个当前对象。白日／暗夜尺寸与行为一致；320、390、768、1024、1440、1920px 下节点、引用和详情可用，断点变化不重置上下文。完成 T01–T03、T07–T11 的界面部分及 E09–E10，持久化与事务行为在后续里程碑补齐。

### M2 · 故事稿与预处理

**工作内容**

- 新增项目级改编稿及来源映射，原文 hash 与内容保持不变。
- 实现范围选择、精简／扩写／节奏调整目标、受保护事实与人工编辑。
- 对处理任务保存输入版本、幂等键、输出文本、变更清单与审核状态。
- 实现差异查看、保存草稿、直接使用原文、采用新稿及变更预览。
- 处理新增内容、删减范围与重组，明确采用稿覆盖校验，不沿用「原文全部段落必须连续覆盖」作为所有模式的唯一标准。

**出口标准**

精简与扩写真实产生可复核的结果；保存不改变采用稿；采用不隐式生图；错误／超时／过期结果不会替换当前依据；原文不丢失。目标长度显示为目标或测量结果，不冒充已经保证的输出。

### M3 · 故事结构与分场编辑

**工作内容**

- 实现真实父级、可选嵌套制作分组与稳定场／镜头 ID，显示序号与业务 ID 分离；原文章节与制作集属于不同分支。
- 短故事可直接分场，分章节／分集故事按选定范围规划。模型执行按窗口进行，作品总结构不受旧 10 段／24 镜限制。
- 实现场目的、人物、地点、来源、入口／出口连续性与预算编辑。
- 提供拆分、相邻合并、重排、移动到合法父级及来源覆盖检查；先预览旧／新路径、衔接与影响，再采用。
- 服务端在同一事务中校验父子类型、无环、项目归属与 expected_version，更新父级、顺序和影响摘要；失败没有半次移动。子树范围在任务提交时冻结，后来移动／新增节点不改变已提交任务。
- 采用结构变更时更新依赖标记，确认分场另行保存，不自动生成下游素材。

**出口标准**

跨章节来源关系清楚；拆分／合并／移动不重编号无关对象或改写旧发布；已生成范围的影响清单正确，相邻衔接复核与整场重做分开。树层级不能仅在前端模拟；可处理超过旧总镜头上限的逻辑计划，仍遵守单次服务限制。

### M4 · 共享素材、版本与采用范围

**工作内容**

- 复用现有身份／服装／场景规范与参考图规则，建立素材版本列表和使用位置查询。
- 同一人物支持多套独立服装；同一身份与服装版本支持跨场复用。
- 保留唯一素材节点，人物下展示所属服装。共享素材分支显示关系卡／表，画布旁显示使用中版本与数量；选中某版本后高亮准确引用场及镜头并显示虚线，素材详情给出各版本的使用路径，场／镜头显示共用范围。
- 使用位置显示完整路径、准确版本、引用类型与有效性；支持双向定位及原上下文返回，区分当前草稿与历史发布，不把不同版本合并成「共用同一版」。
- 服务端保存具体版本的审核；新版本不自动替换现有镜头引用。
- 实现「采用到当前场／指定场／适用的未发布草稿」及影响预览。
- 保留自然体表的服装模式结论、本地拼接参考板与准确依赖，不新增定装合成／试拍／逐镜生图。

**出口标准**

创建、确认、采用三种动作各自可验证；刷新后确认保持。用户能看见一份身份如何跨场共用、不同服装如何归属、同一服装各版本分别用于哪里，并双向定位；计数与实际绑定一致。只有明确采用的新版本引发对应下游复核，旧发布不变。

### M5 · 分场制作与逐对象审核

**工作内容**

- 将 author 页面拆为统一树选择上下文、场／镜头编辑器、引用检查、分镜、审片与次级任务记录；保留专业计算节点独立职责。
- 场与镜头摘要、树节点、镜头详情共用稳定 ID、版本和审核记录；父级状态汇总真实子项，不从父级确认全部后代。
- 实现逐版本确认，移除总 confirmed 勾选机制；将范围选中状态与作者审核分开。
- 「确认分镜」与「生成本场视频」分开，生成入口由服务端就绪检查决定。
- 状态细分为执行、审核、有效性和发布，不将任务完成等同于作品确认。
- 局部修改只产生局部新版本；其他有效确认保留。后台响应不抢焦点、不自动跳页。
- 确认／生成／修改操作具有重复提交保护，失败、待核实、过期输入均能恢复。

**出口标准**

一场从引用到分镜到成片可完整操作；未就绪按钮有具体修复入口；只改一项不会清空全部审核；刷新、回看、前后导航和迟到响应均正确。

### M6 · 发布与变更闭环

**工作内容**

- 发布页支持选择已完成的场／集范围，展示所有就绪条件及实际选用版本。
- 创建不可变发布快照；新素材、新稿、新结构只作用于明确采用的草稿范围。
- 对变更预览和应用加入 expected_version，过期预览需重算。
- 区分原文改写的确定依赖与叙事影响候选；处理后续知识、道具、地点等事实变化。
- 明确继续／重试／待核实／整轮重做的行为，普通修改不调用删除型重做。

**出口标准**

发布后继续制作或改稿，旧版本仍可播放且引用不变；新发布版本可区分；部分失败不会进入发布；输入版本变化时无法用旧预览应用修改。

### M7 · 验收与收尾

**工作内容**

- 执行下方用例、当前相关回归与类型／构建检查。
- 真实浏览器点击验证双主题、全断点、键盘、减弱动态偏好与长内容。
- 对生产路径完成小范围实测。付费任务需在已授权的测试范围内执行，记录真实任务与产物；不能以 fixture 或录屏冒充真实执行。
- 完成旧项目兼容检查与必要的数据迁移说明，整理截图、操作证据、命令结果和未覆盖项。

**出口标准**

所有必需用例通过；没有阻塞数据错误、混搭主题、丢失确认或旧发布被改写；未实现的后续功能无误导入口。

## 3. 建议修改位置

以下是拆分建议，不要求照搬文件名；职责边界必须保留。

| 区域 | 现有位置 | 建议职责 |
| --- | --- | --- |
| 原文与改编 | `backend/story_sources.py`、`director.py`、`authors.py` | 原文读取与新改编稿服务分离；导演任务明确采用稿版本和范围 |
| 项目归属 | 新项目节点服务，沿用现有 Record 基础 | 唯一归属、节点查询、类型约束、树版本与原子移动；统一领域实体的父级 |
| 结构与单元 | `backend/segments.py`、`production_nodes.py`、`workflows.py` | 制作子树、计算窗口、稳定 ID、范围解析、结构编辑与旧版兼容 |
| 素材与影响 | `backend/asset_workflow.py`、`preproduction.py`、`consistency.py` | 并存版本、精确绑定、按版本使用查询、确认和影响分析；保持图片引用规则 |
| 镜头与发布 | `backend/production.py`、`video_storage.py`、`worker.py` | 冻结任务输入、逐镜选用与审核、发布快照和过期回包隔离 |
| 项目工作区 | `web/app/author/page.tsx`、`SegmentReview.tsx`、`AssetRedesign.tsx` | 项目树、唯一选择上下文、面包屑、对象编辑器、共用关系及双向定位 |
| 进度与恢复 | `ProductionProgress.tsx`、`production-progress.css`、相关接口 | 真实状态与处理入口，任务树作为辅助，不覆盖当前编辑对象 |
| 视觉与入口 | `globals.css`、`ui-controls.css`、`ui-motion.css`、`author.css`、`ReaderHero.tsx`、`StoryImport.tsx` | 共享主题和组件规则、市场锚点、独立导入、响应式与动效 |

不要把整个工作台改写成一个状态对象加大量条件渲染。查看状态由 UI 管理，审核／引用／任务就绪由服务端持久化与验证。

## 4. 开发提交建议

按里程碑分批提交，每批附实现范围、契约变化和证据。任何破坏兼容的模型调整先提供迁移／回退路径。

建议每批说明：

1. 实现了哪些规范条款与验收用例。
2. 涉及哪些数据结构、接口与状态转换。
3. 已执行的检查与真实结果。
4. 当前未接通或仅有 fixture 的部分。
5. 现有项目和历史发布的兼容情况。

不要求以固定天数推进：M0 的实际差异决定后端改造量。避免先承诺时间，再以删减版本或来源机制赶进度。

## 5. 验收数据与证据

| 样本 | 需要覆盖的情况 |
| --- | --- |
| A · 短故事 | 无章节，直接分场，可跳过预处理，至少一条完整制作与发布路径 |
| B · 分章节故事 | 多章节、跨章节改编来源、超过旧总镜头限制的结构计划、只处理选定章节 |
| C · 分集故事 | 原文章节与制作集不同，部分集发布，后续集尚未制作 |
| D · 人物复用 | 同一人物两套服装，至少两个场复用同一版本；另一个场换服装 |
| E · 局部修改 | 发布后新建素材版本、仅采用到一场、检查受影响与保留范围 |
| F · 恢复与并发 | 明确失败、超时结果未知、离线刷新、过期响应、重复提交、预览后版本变化 |
| G · 界面压力 | 长标题、很多场、多角色、打开修改区、无封面、空项目、错误长文本 |
| H · 项目树 | 无分组短故事、嵌套分组长故事、折叠祖先、跨组移动、合并后恢复、非法父级／环、提交后子树改变 |
| I · 共用关系 | 同身份多服装、同素材不同版本、同版本跨场、多镜头共用、未使用素材、旧发布引用与当前草稿不一致 |

本节仅供开发后的验收选取证据，不在每轮设计或每次小改动中执行完整矩阵。界面实现后按实际变化检查主页／导入、相关画布、对象编辑与发布，保留必要的明暗主题和代表性尺寸证据；旧「章节编排」检查项随新制作模式替换。共用关系证据显示准确版本、实际路径和选中范围。检查通过后不无故重复或扩大测试。

行为证据必须包含操作前后的对象／版本／引用／审核及发布摘要。生产证据包含任务 ID、输入版本摘要、产物及来源类型。任何自建测试数据都标记为 fixture。

## 6. 验收清单

以下复选框用于开发后的实施验收，不代表产品的审核交互，也不代表设计任务进度。旧布局相关条目待对应设计任务定稿后改写；骨架阶段不执行本清单。开发时针对实际改动选择必要用例，按依赖补齐证据，不每轮重复全量测试或等待无关后台任务。

### 项目树与归属

## 8. 验收结论与缺陷等级

| 等级 | 示例 | 处理 |
| --- | --- | --- |
| 阻塞 | 原文丢失、归属循环／重复、移动丢失子项或引用、旧发布被改写、错误版本入片、重复付费请求、无关场被删除 | 不通过，修复后重新验证相关闭环 |
