# 工作台框架记录与后续工程计划

版本：2.4 · 2026-10-05 · 状态：F0–F4 框架已完成；来源工作台前端（A1–E，见 §7.4）已实现并提交；服务端契约（D03/D02/D06）待细化

第 1–6 节保留已完成 F0–F4 的范围与验收记录，包括当时的四标签和无左侧栏结构；它们不再约束最新来源工作台布局。第 7 节同步本轮已确认设计的后续工程拆分，尚未启动实现。导航、精确范围契约及其余制作操作继续在对应 D 任务细化，交互稿不能直接当作完整产品。

方向依据：[画布设计方向](canvas-design-direction.md)与[设计任务骨架](design-task-skeleton.md)。本轮只更新设计、任务及验收点，不重开已完成框架，不宣称正式保存、范围迁移、Agent 接入或剪辑内核已完成。

## 1. F0–F4 目标和完成边界（历史记录）

交付一个能承载后续工作方式的真实前端框架，**以项目（project）为核心**：项目顶栏（展示项目身份与进度）、故事／制作／素材／成片四个工作区（该项目的视图，故事为来源素材）、主体画布、右侧上下文区域、基础组件和页面状态。

本期完成后停在框架验收，不继续实现预处理、分镜编辑、素材生成、审核、生产调度、剪辑、发布或导出。不会为预留入口提交任务，也不改造后端业务模型、数据表或供应商流程。

| 区域 | 本期确定的结构 | 后续待讨论 |
| --- | --- | --- |
| 项目顶栏 | 项目名称、四个顶部标签、统一主题入口 | 新建、导入、项目管理的具体操作 |
| 故事 | 稿件与剧本的内容容器 | 精简／扩写、剧本编排、差异与采用 |
| 制作 | 无限画布；多场景分组，每组整齐排列多个镜头 | 拆镜、人物与场景分配、衔接、生成与审核 |
| 素材 | 无限画布；资源节点及生成内容的容器 | 生成条件、参考输入、上传、结果比较与选用 |
| 成片 | 独立的编辑工作区容器 | 镜头库、轨道、蒙太奇、剪辑内核和交付 |
| 右侧区域 | 可开合的上下文面板，内容通过插槽提供 | 属性、引用、任务的具体内容及点击逻辑 |

左侧常驻侧栏删除，不预留空列，也不将同一套图层／素材／选择工具换个位置堆回去。右侧不设独立「版本」入口。本期右侧入口采用现有样式稿的属性、引用、任务、定位；具体功能只留插槽，不作为已定稿操作。

## 2. 框架的工程边界

- **导航与视图状态**：当前项目、当前大标签、所选展示对象、右侧面板开合、各画布视野和布局偏好由前端管理。对象内容、正式引用、审核和任务状态保持现有服务端权威。
- **视图与业务分开**：平移、缩放、自由摆卡和整齐排列只改变展示位置，不改归属、镜头顺序、素材绑定或确认状态。框架不实现拖线绑定、跨场投放、拆合、批量勾选等未讨论操作。
- **切换由用户发起**：点击顶部标签才切换工作区；后台更新及查看对象不自动跳标签。框架保留每个工作区的视图状态；未保存业务编辑的处理以后再讨论，本期没有业务编辑表单。
- **内容可替换**：画布与右侧面板依赖展示数据和内容插槽，不嵌入生成、确认或发布的流程判断。故事、制作、素材、成片分别有工作区组件，避免新增一个巨大的条件渲染页面。
- **统一外观**：亮色延续工作台，暗色延续主页。框架统一表面、文字、边线、按钮、输入框和面板层级；业务卡片和复杂动效在对应操作讨论后细化。

顺序为 **F0 → F1 → F2 → F3 → F4**，每批单独提交、单独验收，不一次替换完整生产工作台。不以固定天数承诺工期；F0 核对现有代码后，再给当前批次的工作量估计。

### F0 · 入口与接口

- 在 `web/app/author/workbench/` 新建工作台入口，保留 `work` 项目参数；本期不直接替换原 `/author` 的生产流程。
- 顶部空间标识固定为 `story / production / assets / release`。旧流程的 `stage` 与用户查看的工作区分开，不能用后台阶段强行切换页面。
- 展示模型只定义稳定对象标识、节点种类、标题、位置和分组等框架字段。正式故事结构、资源关系及保存模型留待后续讨论。
- 视图状态按项目和工作区隔离；切换时在会话内恢复，刷新回到合法默认视图。跨设备或服务端保存不在本期范围。
- 画布**引用 React Flow（`@xyflow/react` v12，旧包名 reactflow）**实现平移、缩放、适配、自由摆卡与按场整齐排列，自定义节点渲染展示对象；本期只用其视野/节点视图能力，**不开放连线编辑、多选、批量**（留待 D02/D05），依赖在 F2 以 `pnpm add @xyflow/react` 引入。详见 [F0 契约](f0-framework-contract.md)。

### F1–F2 · 外壳和画布

- 顶栏、标签与内容区共享一个工作台状态入口；右侧面板可关闭，关闭后画布重新获得空间。
- 画布节点和分组使用可替换的渲染器。制作默认采用「场景分组 + 横排镜头」，素材使用独立资源节点，不添加制作组合层。
- 保留视野操作与展示排布；排布坐标单独记录。画布组件不从坐标推断业务归属或叙事顺序。
- 右侧仅接选中对象的只读摘要或占位内容，不移植样式稿中的素材编辑表单、生成表单与版本浏览器。
- 基础主题和面板转场遵循系统的减弱动态偏好。复杂卡片动效不在框架阶段展开。

### F3 · 接入与兼容

- 通过只读适配层读取当前 `/api/author/projects/{id}` 返回的数据，保留原页面入口和现有任务恢复路径。
- 每个工作区独立接入；现有数据不支持的场、剧本或剪辑内容显示明确空态，不创建临时业务记录补齐展示。
- 多场、多镜头样式使用隔离的示例数据，不能写入真实项目，也不能用示例证明后端已支持新故事结构。
- 后台任务更新只刷新相关摘要，不抢当前对象或工作区。框架不新增任务轮询与自动执行链。

## 5. 本期验收与验证预算

只验证框架，不执行完整生产验收清单：

- 四个大标签能切换；没有左侧常驻栏、空列或右侧版本入口。
- 多场景、多镜头可整齐展示，画布与右侧面板互不遮挡关键控制。
- 平移、缩放、自由摆卡和整齐排列不改业务状态；切换空间保留会话视图。
- 白日／暗夜完整一致；在一个桌面尺寸和一个窄屏尺寸走查，发现具体问题才补相关断点。
- 空项目、只读载入失败与对象缺失有可理解的显示；原工作台和历史项目入口可用。
- 关键控件保留原生键盘焦点，面板开合可返回触发位置；没有生成、审核、发布等假可用按钮。

开发后按实际改动运行 `pnpm typecheck`；涉及 Next.js 路由和组件集成时运行一次 `pnpm build`。只补有行为意义的框架状态或适配测试，不为间距、颜色和按钮存在与否编写测试。仅在失败、修改或未解决问题时复验。

不运行全量后端测试，不调用模型或媒体供应商，不等待生产任务完成，不安排截图矩阵和长时间轮询。计划文档交付只检查链接、内容一致性和 Git 差异；本文没有宣称这些开发验收已执行。

## 6. 框架完成后的讨论边界

F4 通过后，分别讨论故事处理、分镜创建与衔接、人物和场景归属、素材生成与输入、关系编辑、任务及审核、剪辑、发布和导出的操作。讨论结果确认后才补业务接口、数据契约、详细状态和开发安排。

当前框架没有替这些操作定稿；已有样式稿中的点击、表单、关系开合和时间轴均为讨论素材。旧全流程计划、剪辑内核候选和完整验收用例可从 Git 历史追溯，不作为本期执行要求。

## 7. 本轮确认设计与后续工程安排

### 7.1 已确认的设计输入

以[来源工作台交互稿](prototypes/storyloom-source-studio.html)和[当前设计方向第 7–11 节](canvas-design-direction.md#7-故事总控连续原文与荧光片段)为依据：

- 左侧连续全文阅读，仅用完整荧光区域表达片段；片段视图从真实对象动态生成，可点击跳转。划选、建候选、确认分开，范围连续非空且不重叠，边界相接允许。
- 切分／裁减、剧本、分镜、资产为无限画布，对象自由拖动。剧本从区域实际边缘单一起点和共同主干出线，再分支到对应对象；几何变化不改来源。
- 成片由剪辑组件铺满右侧主工作区，左侧来源／片段列表作为资源区。资源浏览保持剪辑上下文，明确插入创建独立实例，保留来源及准确版本。
- 属性是所选项目对象的属性；每步骤底部提供不要求显示 Agent 名称的自由对话入口，恢复当前步骤、片段、对象上下文及历史。
- 切换不打断任务；任务结果归属发起时的对象与版本，完成不抢焦点，项目队列可定位原工作位置。顶部标签数量和名称尚未固定。

来源界面可以先用明确的隔离数据验证交互，真实写入必须依赖已完成的服务端契约。对话接口、权限及修改提案、剪辑内核和媒体能力分别确认，不能用本地模拟回复或时间轴示意宣称接入完成。

### 7.3 契约缺口与验证范围

现有 `backend/segments.py` 仍校验段落级 `source_refs`，没有精确文字选区接口。后续先统一字符计数单位、换行处理、正文版本、半开范围及迁移策略，再实现前后端一致校验；不直接用段落序号、显示行或 DOM 坐标持久化范围。旧流程数量预算继续用于旧计算窗口，不扩大为整部故事上限。

正文改写、片段边界调整及拆合需明确影响预览、映射复核和提交版本，保留旧视频、剪辑与发布的文本依据。候选范围允许未分配正文，完整切分提交单独检查明确制作范围的顺序、首尾覆盖和裁减／范围外记录。

本轮只检查文档差异、版本状态、相互链接与规则一致性；设计稿此前已做关键路径走查，不重跑生产测试。后续工程按批次运行有意义的范围校验、状态恢复或媒体适配检查；没有新变化和未解决风险时不重复扩展测试。
